# Windows 常驻模拟交易

这台常开的电脑运行完整服务：评分、腾讯 HTTP 轮询、订单执行、账本、盘后结算与 AI 验证均在本机。关闭浏览器不会停止服务。电脑睡眠、关机、断网或 Docker 停止期间不能交易；恢复后继续未完成订单，不补造停机期间的成交。

本机账户和现有 Sites 私有网页的 D1 账户分别保存，**实时交易与收益以 `http://localhost:3000` 本机页面为准**。本机没有复用网页会话、云端绕过令牌或短期凭据，也不会上传本机密钥及账户数据库。Sites 页面继续提供私有复盘和盘后任务；单独的 Sites 托管没有秒级常驻行情进程。

## 首次启动

1. 安装并启动 [Docker Desktop for Windows](https://www.docker.com/products/docker-desktop/)，按安装程序要求启用 WSL 2，使用 Linux 容器。
2. 从 [GitHub 仓库](https://github.com/sanchez0623/ashare-limit-lens) 下载 ZIP 并解压，或 `git clone`。
3. 双击 `scripts/windows/start.cmd`。首次启动会用记事本打开本机 `.env`；填写 `AUTH_PASSWORD`，至少 16 位。用户名默认为 `owner`。
4. 如需真实 AI 审计与策略改进，再填写 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`。保存并关闭记事本，回到窗口按键继续。首次构建需要下载镜像与依赖。
5. 打开 `http://localhost:3000`，使用上述用户名和密码登录，在“模拟交易”的“自动执行状态”确认“常驻执行器已连接”。交易时段显示实时观测次数、报价状态、逐单进度和成交；盘外显示等待状态。

初始资金默认 100 万元，费用为图中的六项默认值，均在账户设置中调整。初始资金在第一次盘中执行会话开始后冻结；费用修改只用于后续新计划。首次盘后结算建立基准并冻结下一交易日计划，次日开始自动执行；不使用当天收盘评分补做当天交易。

顶部系统菜单中的“数据管理”可分别更新股票名册、东财行业和申万三级分类。名册优先读取交易所，失败时用新浪补齐，无需 Key，东财故障不影响名册发布。申万默认使用理杏仁批量接口，在本项目 `.env` 配置 `LIXINGER_TOKEN` 后重启服务；凭证只供后台 worker 使用。首次安装需点击更新初始化；更新 worker 独立于自动交易，关闭浏览器后仍继续执行。数据与任务保存在同一个持久数据卷中，详见[数据管理说明](data-management.md)。

## 开机恢复与每日执行

新版三维市场环境随下一份尚未执行的盘前计划启用，启动前自动保存数据库备份并保留旧计划修订；已到09:30或会话开始后不改写当日计划。部署代码不会自动重启服务，重启由操作者执行。三组对照及买点统计在系统设置的评分页查看，规则见[市场环境实施说明](design/market-environment.md)。

- 在 Docker Desktop 设置中开启登录时启动 Docker Desktop；Compose 已设置 `restart: unless-stopped`，Docker 恢复后容器自动恢复运行。
- Windows 电源设置中关闭自动睡眠，保证交易时段联网。仅设置显示器关闭不会影响服务。
- “从不自动睡眠”仍不能阻止手动睡眠、合盖睡眠或其他程序调用睡眠接口。验证日从开盘前到 17:00 核验期间保持电脑唤醒、接通电源和常驻服务运行；需要让本机睡眠时，应将服务及所需本地数据放在另一台始终开机的电脑或服务器上运行。
- 默认每 10 秒发起一次 HTTP 轮询；前一请求未结束时顺延，避免重叠，可在 `.env` 修改 `TRADING_POLL_SECONDS`（3–60 的整数）并重新运行启动脚本。无 WebSocket 和券商交易连接。
- 盘外通常每 30 秒检查，临近 09:30 和 13:00 自动缩短等待并对齐开盘；准备完成后以实际时刻采集，避免用准备前的时间误判为尚未开盘。网络与系统阻塞仍可能影响覆盖，盘后按真实记录核验。
- 连续竞价 09:30–11:30、13:00–14:57 运行订单；午休等待。14:50 起尝试恢复做 T 第二腿；收盘后 15:05 起自动复盘、更新估值和收益、冻结次日计划，失败后间隔 5 分钟重试。非交易日通过指数日期校验跳过。
- 龙头练习另在15:00—15:05归档真实收盘帧；每日全账户AI复盘继续保存，周五17:15由独立告警进程向已配置飞书发送一条摘要。研究完整日要求连续观测间隔至多20秒，断流日期仅作诊断；设置更慢轮询不会变成合格研究样本。具体规则见[练习研究闭环](design/practice-research.md)。
- 配置飞书机器人后，独立告警进程按现有轮询间隔（默认10秒）检查主账户已落库成交并推送：北京时间、股票、动作、实际份额、成交价、费用与截至该笔的订单进度。15:05后且结算成功时发送当天完整逐笔明细、买卖金额、当日费用、含费损益、未成交订单和收盘持仓；零成交明确提示。明细较长时自动分段，不截断第100笔之后的数据。只发送主账户实际成交，影子账户和挂单不计作成交；首次盘后启用只发送当天汇总，停机期间没有成交的记录不补造。
- 交易通知复用 `FEISHU_WEBHOOK_URL` 和可选 `FEISHU_SECRET`，可用 `TRADE_NOTIFICATIONS_ENABLED=false` 单独关闭。迁移0037保存消息及发送状态；并发与重启按交易周期、成交ID或交易日去重，明确限流按分钟退避、最多5次；网络超时或进程在发送中退出时记为 `UNCERTAIN`，不盲目重复。`GET /api/alerts/status` 的 `trading` 返回队列状态和最近发送结果。飞书加签按[官方协议](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)将时间戳和签名放在JSON请求体中。
- 暂停自动交易可双击 `scripts/windows/stop.cmd`；再次双击启动脚本恢复。不要运行 `docker compose down -v`，它会删除账户数据卷。

服务只映射到本机 `127.0.0.1:3000`，不向局域网开放。需要远程访问时，应明确配置 HTTPS 和访问授权；不要直接改为公网端口。

## 数据保留与核验

行业输入使用按股票代码绑定的已发布东财行业快照，冻结计划记录行业快照版本，盘中按同一版本归组；后来更新行业表不会改变已冻结计划的分类。行情源原行业文本保留以便核对，历史查询不使用之后才发布的分类。旧历史补全脚本的手写数字行业对照表已停用。

服务启动后、交易及评分进程启动前，会检查当前空仓零成交练习周期的行业归属。若原价格信号冻结前已经存在可验证的东财行业表，先生成 SQLite 备份，再事务性修正行业引用；82 只等既有观察名单、价格历史、费用和风险参数保留。原计划及修复前观测、联合行情帧和评分完整归档，可从交易历史下载。原价格信号冻结时刻保留，真实修订时间单独记录；从重启后的新报价建立确认，不按修复前行情补造交易。已成交、已有订单或持仓、存在活动研究或影子账户时拒绝自动修订，保留原数据并显示阻断原因。

已完成行业修正、尚未显式绑定快照的旧会话，若已经下单或成交，重启时不会再次修订或清空会话。启动程序先用当前执行代码重放全部原始观测，逐项核对会话、账户和成交，再为原冻结计划追加不可改写的续跑证明，并固定使用原行业修订引用的快照。证明绑定原计划、原观测前缀及当前执行指纹；后续代码变化须重新核验。已有成交、持仓和原始记录保留；登记前未消费的联合行情帧继续留档，从登记后的新行情恢复执行。任何行业差异、来源缺失或重放不一致仍会阻断启动。

新计划冻结 `adaptive-entry-order-v2` 订单恢复规则：预热确认不足、临时缺行情时暂停剩余买入并保留数量；有效确认恢复后继续检查买点、容量和风险预算。新鲜观测已证明风险超限、账户熔断或订单到期时仍取消余单。旧会话通过续跑证明在明确的新观测边界启用该规则，原始观测仍按原规则重放；已经发生的撤单记录和原有效期不会重写。未来配置的排队引用独立保留，不参与当前冻结计划的执行状态比较。

动态状态恢复使用 `dragon-adaptive-risk-v2`：断流重置阈值为 3 分钟，市场、板块和每只股票分别判断；短时缺失暂停使用过期数据，同时保留已确认状态和历史样本。恢复的新鲜数据可沿用确认，重复缓存不增加确认次数；缺少连续样本的趋势判断与预算改善继续等待。15 秒报价新鲜度、90 秒市场数据有效期和 20 秒增量成交量连续性限制独立保留，不能把中断期间的累计成交量补成可交易额度。启动保护阻断时健康接口显示 `BLOCKED`、`automatic=false`；网页可访问不代表后台交易循环已启动。

备用日线接口按股票逐只请求，不设候选总数 100 只的截断。每轮先读取完整范围的已验证缓存，再以两个并发请求补齐缺失记录；单轮时间预算仍为 45 秒。显式 `maxCodes` 仅限制本轮新请求数，重试继续未完成的股票，不重复占用已缓存股票的预算。`pendingCodes` 表示尚未处理的股票，`failedCodes` 表示已尝试但未获得有效配对日线的股票；未处理记录不能当成资格不符而冻结观察池。尚未绑定计划的部分快照可在盘后重试补齐，已经冻结的来源不能静默覆盖。

17:00 是独立观察的准备和核验窗口，不会重写主账户已有冻结计划。修订尚未执行的独立政策计划可运行 `node scripts/repair-pending-history-plan.mjs` 预览，确认结果后加 `--apply`：先保存 SQLite 备份，再事务性保留旧计划和输入、重建信号快照与下一交易日计划、核验完整账本重放。修订沿用原配置、成本政策、行业版本和运行构建，不修改持仓、资金或历史观测。计划已被会话使用、已冻结同日影子计划、存在活动主账户研究或超过盘前窗口时拒绝修订。可用 `--database 路径` 对数据库副本验证。

账户保存在 Docker 的 `paper-data` 数据卷，容器重建及普通重启不删除记录。页面可下载完整 JSON，再用 Node.js 24 执行 `npm run verify:paper -- 记录文件路径`；也可直接点击“核验收益”。盘中核验包括已提交的实时成交，盘后核验额外比较每日权益与收益率。重要交易记录定期导出保存，完整 JSON 含账户信息，不应提交到公开仓库。

已验证四个多日完整轮次：建仓→加仓→减仓→清仓，底仓→正向 T→反向 T→清仓，新仓止损→T+1 延续→跌停恢复→清仓，以及反向 T 第二腿阻塞→次日恢复→清仓。测试使用明确标注的合成行情，验证流程和核算，不代表真实收益。

## 独立评分进程

用户可在盘后结算完成后预约下一交易日清仓：`node scripts/request-paper-exit.mjs --code 股票代码 --trade-date YYYY-MM-DD --reason 原因`。指令按当前持仓周期登记，迁移0038保留不可改写的独立依据；命令先备份数据库，不修改现金、份额或历史成交。服务在启动并获得监听端口后、各后台进程启动前升级执行版本，并把指令冻结进尚未执行的主账户计划。程序仍须在指定交易日09:30前重启加载；控制台会显示 `[manual-exit] 已冻结...`。同股当天禁止新买、加仓及做T；其他股票继续正常观察。清仓按有效报价、T+1、买盘和区间成交容量执行，未卖完继续保留退出状态及后续计划指令，不保证开盘立即全部成交。成交纳入原账本和飞书明细，清仓不清除历史，也不自动重置收益基准。已经执行的计划不能事后加入该指令。

主服务和数据更新、评分、统计、告警子进程的控制台日志统一使用北京时间，格式为 `[YYYY-MM-DD HH:mm:ss.SSS +08:00] [进程标识] 内容`。多行输出逐行保留时间，父进程转发子进程输出时不重复加前缀。数据更新进程记录就绪 PID、异常、退出码和两秒后的重启；异常清理后关闭 IPC，避免进程残留而无法被父进程重新拉起。下载和维护命令的 JSON 输出格式保持不变。旧版已输出的无时间日志无法反推准确发生时间。

常驻服务构建并重启后会启动独立评分进程，按已经持久化的观测生成六类买点评分及完整周期校准，不改变模拟交易。启动时追加迁移0034；无需清库或重置账户。可用 `SCORING_WORKER_ENABLED=false` 禁用。规则、只读接口与验收见[分层评分文档](design/observation-scoring.md)。
