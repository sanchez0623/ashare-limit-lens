# 模拟交易与收益核验

## 时间与数据

常驻 Node/容器服务在北京时间 15:05 起自动调用盘后更新，失败每 5 分钟重试；Sites 网页保留独立的 15:30 盘后任务调用 `POST /api/run-daily`。服务端在 15:05 前不归档、不结算。涨停评分保存当天第一份快照；盘后计划只用于下一实际交易日。执行时检查计划冻结时间早于交易日 09:15，禁止当天收盘评分参与当天成交。

V5盘中条件执行与 `dragon-risk-v1` 新政策的准备和冻结截止为09:30前，未标记的旧开盘计划保留09:15截止。独立影子观察从17:00开始核验，15:05常规盘后更新不提前出具影子核验结论。

账户首次结算只建立收益基准，不追溯执行已有历史评分。每日行情、计划、成交、权益持久化；行情日期不匹配、持仓价格缺失、昨收与上一账面价格不同或缺少相邻交易日结算时暂停，保留资金和错误状态。除权、分红、送股目前需要核对处理，不能作为普通价差计入收益。系统不补造历史快照。当日评分源缺失但持仓行情可结算时，只生成明确标注的防守计划，停止新增和做 T，保留旧仓止损、止盈与最长持有期保护。

东方财富涨停池决定评分覆盖范围：沪深主板及创业板，排除 ST、科创板与连续一字新股。腾讯日线确认交易日、开收盘价和涨跌停价；实时 HTTP 报价用于确认实际模拟交易顺序，分钟行情保留用于旧版历史重放。公开接口可能限流或停止服务。

历史日期页面优先读取同一服务数据库中的盘后归档，保留当天冻结的个股、板块和情绪评分，不按当前权重重算。旧版归档未保存的炸板池和封板率显示为“—”；新归档同时保存原始行情与完整统计。当天页面仍优先实时来源，来源失败时可读取已保存的当日归档。页面会明确标注“历史归档”和归档时间。

晋级率兼容当日涨停池的 `lbc` 与昨日涨停池的 `ylbc`（昨日连板数），优先使用 `lbc`。昨日有效连板样本无人晋级时显示 `0%`；缺少样本或有效连板字段时显示暂缺及原因。旧归档的晋级率为空、但保存了当日和昨日涨停池原始数据时，只在展示中补算晋级统计并注明来源，不改写快照、冻结评分或研究输入摘要；已有晋级率（包括 `0%`）保留。原始数据缺失或无效时继续显示暂缺，不联网补造历史样本。

没有归档时仍尝试公开历史来源，日期不匹配则拒绝展示，并注明请求日期、来源日期和归档缺失；查询不会补造事前评分。Windows 本机 SQLite 与托管网页的 D1 独立，只有保存归档的服务能读取对应历史。

## 计划与成交

基准策略：个股评分至少 80、行业板块分至少 55、指标覆盖至少 80%；不追逐 5 板以上、一字特征或高换手样本。最多 4 个持仓。情绪分对应目标仓位 55%、35%、15%，情绪不足 40 时不新增仓位。建仓和加仓在次日 09:30–09:35，包含滑点的买价不得超过事前上限。减仓和清仓在连续竞价时段持续重试；开盘窗口结束后取消剩余普通买单。减仓、退出和做 T 第二腿未完成时记录剩余量并延续至下一交易日，保护退出优先。成交不足保留实际份额，未成交不计费用。

持仓可按照评分延续、目标仓位、盈亏、持有时间生成建仓、加仓、减仓、清仓、正向 T、反向 T 或持有动作。默认止损 6%、分批止盈 12%、最长观察期 5 个结算日。持仓的事前保护阈值通过实时轮询触发，优先取消冲突的普通计划及做 T。新买份额遵守 T+1，触发退出后将不可卖部分延续至下一交易日；不伪造当天止损成交。

硬约束：单股买入仓位上限 20%、总买入敞口上限 60%、账户回撤达到 10% 后规划清仓并停止新增仓位；价格波动、跌停和部分成交仍可能使实际风险超过阈值。不透支、不融券；买入 100 股整手。新计划默认采用 `TIME_LIQUIDITY_V1` 成本模型（见下节）；旧计划与旧导出仍按原模型重放：采样价加固定 10 bps 滑点，最多参与两次新鲜报价之间实际新增成交量的 1%，同一代码本轮的所有订单共享此额度。第一条报价只建立累计量基准；断线超过 20 秒、陈旧报价超过 15 秒、重复或倒序报价不提供成交额度。触及涨停不假设买入，触及跌停不假设卖出。当前交易不采用日线开盘价补造成交。旧版导出仍按原模型重放，保留其开盘价假设标记；两种模型都无法模拟盘口排队。

### 执行成本模型 TIME_LIQUIDITY_V1

新冻结的计划默认携带完整的执行成本政策（版本、摘要与校准状态），成交价由模型计算：买入向上、卖出向下按分取整。成本包含四个成分：按时段递减的残余项（09:30–09:31 为 30bps、09:31–09:35 为 20bps、09:35–10:00 为 10bps、其余连续竞价 5bps）、昨日涨停标的 15bps 风险项（来自计划冻结的昨日涨停名单）、数量冲击（参与率达到参考值 1% 时 10bps 的单调曲线）与价差项（腾讯买一/卖一可用时按不利方向锚定，缺失时使用 5bps 隐含价差回退）。分钟采样重放的残余项按 1.5 倍计，历史回测与实时轮询分别声明精度，不冒充同精度。

同股同一报价区间内，保护单、普通卖单、买单和做 T 两腿共享绝对成交容量：买入不得超过区间新增成交量的 1%（开盘半小时另有 0.5% 软上限），累计冲击按区间内已成交数量递增，拆成多笔不会降低模型冲击。含成本价格超过事前买入上限或触及涨跌停保守边界时如实缩量或不成交；模型成本超出 300bps 适用域时拒绝，不截成更便宜的成交。缺分钟数据时日线假设开盘不再产生成交，仅标记为观察。每笔成交记录完整成本分解（各成分 bps、量比、区间游标、取整成本），可在导出中独立重放核验。

政策参数可在后端校验后自定义（拒绝未知字段与越界值），修改产生新版本并从下一个尚未冻结的计划生效；AI 提案白名单不含这些参数。活动研究窗口内不允许更换政策。探索性压力情景在 `POST /api/research/execution-sensitivity` 中重放；正式赛马在提案前冻结基准/1.5/2 倍情景，逐一重跑候选、父策略和固定基线，全部通过经济闸门才可晋级，不影响主账户。独立真实执行校准流程、输入格式和发布要求见[成本方案 §9](design/opening-execution-cost.md#9-批次-cd-已实施接口与使用)。全部参数是工程先验与压力假设，不是已测得的市场成本；`npm run verify:execution-cost` 可独立验证政策摘要、成本分解、共享容量与版本分派。

实时做 T 以已观察到的报价和可卖底仓执行，两腿不能使用同一次报价。14:45 后不开启第一腿，14:50 起按当时可交易价格尝试恢复第二腿，可能兑现亏损；14:57 起停止连续竞价模拟。正向 T：先在事前低吸线买入，再在更晚时间的兑现线卖出旧仓；反向 T：先卖旧仓，再在更晚的低吸线买回。默认操作底仓的 20%，上下触发线为前收盘的 ±2%。第二腿未成交时保留实际新增或减少的仓位。未完成的第二腿在次日生成恢复订单；若保护退出触发，则取消恢复意图，按照保护订单管理实际持仓。不能用日线最高、最低价虚构先后顺序。

默认模拟资金为 100 万元。首个交易计划开始执行前可调整初始资金；如果仅完成首次空仓基准结算，资金更改会原子更新该基准，并留存旧基准与尚未执行的原计划。开始执行计划后收益基准固定。

所有费用均可在“账户设置”自定义，费率按“万分之”录入。六项分开计算后相加，最低佣金只适用于佣金项：

| 费用     | API 参数        | 默认值                | 方向   |
| -------- | --------------- | --------------------- | ------ |
| 佣金     | commission_rate | 万 0.5（0.00005）     | 双边   |
| 最低佣金 | commission_min  | 5 元                  | 双边   |
| 印花税   | stamp_tax       | 万 5（0.0005）        | 仅卖出 |
| 经手费   | handling_fee    | 万 0.341（0.0000341） | 双边   |
| 证管费   | regulatory_fee  | 万 0.2（0.00002）     | 双边   |
| 过户费   | transfer_fee    | 万 0.1（0.00001）     | 双边   |

例如成交金额 10 万元：买入费用 11.41 元，卖出费用 61.41 元。每项单独四舍五入到分，随后相加。实时部分成交与保护订单按每笔成交分别收取费用，是保守的模拟假设。

费用配置记录版本，并随计划、逐笔成交冻结。在当日盘后修改资金或费用，可重新冻结该日尚未执行的计划，原计划保留在修订记录；盘中修改费用不会重写已可执行的计划，而用于后续新计划。导出包含设置变更和原计划的校验值；旧版无费用配置的历史计划继续使用原三项费用模型。AI 使用当前用户费用比较基线与候选，不能自行修改这些参数；费用发生变化后不能启用按旧费用验证的候选。

API `POST /api/paper/settings` 的 `fees` 对象须包含以上六个参数；费率使用小数比例（例如佣金 `0.00005`），最低佣金使用元。费率范围 0–0.01，最低佣金范围 0–10000 元并精确到分，支持零费率。

策略参数与情绪档位同样可在“账户设置”手动编辑：因子权重（6 个 0–50 整数）、建仓/持有/止损/止盈/做 T 参数（范围与 AI 提案白名单一致），以及情绪档位（两档阈值与三档目标敞口）。情绪阈值同时决定目标敞口档位与加仓、做 T、开新仓、减仓闸门。保存时完整校验（拒绝未知字段与越界值），变更登记为新策略版本 `manual-vN`（evidence 标注 `manual` 与变更项）并切换 `activeStrategy`，原版本归档留档；与费用/风控同一生效纪律——只用于下一个尚未冻结的计划，已冻结计划与历史成交保持原参数。当日盘后修改会重新冻结该日尚未执行的计划。旧策略版本缺情绪档位字段时按默认档位（65/40 → 55%/35%/15%）回退，历史重放语义不变。

## 账本与验证

所有资金和价格使用整数分，卖出按 FIFO 释放旧批次成本，买入费用进入成本。账户、当日行情、权益和成交在 D1 原子批次写入，并用账户版本和运行标识防止并发重复成交。

```text
现金 = 初始资金 + 所有成交现金变动
权益 = 现金 + 持仓数量 × 最新报价（盘后为收盘价）
累计盈亏 = 权益 − 初始资金 = 已实现盈亏 + 浮动盈亏
当日收益率 = 当日权益 / 上一日权益 − 1
累计收益率 = 当前权益 / 初始资金 − 1
```

首次结算日起，以同期主要指数作为收益基准，可在账户设置中切换：默认上证指数，可选深证成指、沪深300、中证500、中证1000、创业板指、科创50；切换后整条基准曲线按所选指数以首个结算日收盘重新起算，历史收益记录保持不变。页面“核验收益”同时检查现金、费用、盈亏等式、计划和行情 SHA-256 值，并按旧版历史或当前实时观测模型重放逐笔成交与每日权益。实时观测、订单阶段、资金和成交原子提交；崩溃和并发重试不会重复扣款。盘中导出也能重放尚未结算的交易日。

下载“完整记录 JSON”后，可脱离网站运行：

```bash
npm ci
npm run verify:paper -- /path/to/limit-lens-paper.json
```

校验失败返回非零退出码。SHA-256 用于发现导出内部数据改变，不是独立第三方签名；自行同时修改数据与哈希不能证明真实性。导出记录包含模拟账户信息，应保存在可信位置。

## 昨日反馈（V5）

保留“昨日反馈”的逐股、板块、AI 评价和历史记录。新生成的反馈按“昨日冻结计划 → 今日实际成交与今日表现”组织，只包含主账户当日实际成交的股票；买入、加减仓、卖出、做 T 与恢复腿均按原始流水汇总，不引入观察账户或研究账户成交。

顶部显示成交只数／笔数、成交标的当日含费损益、实际费用和资料覆盖。逐股分别列出实际买点、动作、数量、成交均价、今日开盘／收盘／最低相对昨收涨跌幅、当日损益、已实现盈亏和收盘浮盈亏。全天最低涨跌幅不是买入后的最大回撤。板块只汇总成交标的的冻结行业归属，不代表整个板块表现。

逐股当日损益 = 当日成交现金净额 + 收盘剩余持仓市值 − 日初持仓市值。已实现盈亏沿用账本卖出成本，剩余浮盈亏按收盘价和剩余账面成本计算；费用已计入现金流和成本，成交价已包含执行成本，不再扣一次滑点或假设卖出费。所有合计只代表当天成交标的，可能与全账户当日损益不同。未完成做 T 保留实际仓位与未完成状态。

反馈仅在北京时间 15:05 后、主账户完成结算后生成，从已归档的会话冻结计划、日初账户、实际成交、当日结算行情和权益读取，不临时拉取行情补算。零成交保存中性“当日无成交”记录；资料缺失逐项标明，不能核验的金额为 `null`，不能按零收益处理。旧仓结算按当时实际政策标记；后续配置变更不会改写已保存结果。

沿用 `GET /api/review`、`POST /api/run-daily`、`POST /api/ai-grade` 与 `reviews` 表。新载荷为 `reviewKind: V5_EXECUTION`、`schemaVersion: 2`，增加 `summary`、`policy`、来源摘要和逐股执行资料；`systemScore` 为 `null`。历史载荷不改写，仍按原评分格式展示。新反馈不登记旧评分 IC／高分组超额，也不将这些旧统计附到 V5 反馈或 AI 输入。

至少一个实际成交标的可核验后，AI 可作描述性复盘；不沿用旧评分反馈的十只股票门槛。AI 主观评分与客观成交指标分开，输入只包含冻结事实和此前同口径、同政策配置的客观摘要，不含过去 AI 意见。无成交或没有可核验样本时不调用模型。反馈和 AI 评价均不改变“人工指定 · 未验证”或研究晋级状态。

## AI 自我改进

新反馈的 AI 审计使用冻结计划及已核验成交；已保存的旧评分反馈继续使用原冻结评分、次日实况及同口径历史客观指标。交易策略改进另有版本流程：

1. 积累至少 30 对相邻交易日的评分与行情，使用前 20 日训练、后 10 日封存验证。
2. 大模型只接收训练信号及扣费后的重放表现。验证窗口行情不发送给模型。
3. 严格校验 JSON 参数白名单、类型和区间，禁止执行代码、改动账本或修改硬约束。
4. 基线与候选在同一封存行情、同一起始资金、相同费用和成交条件下重放；当前实时交易日使用已保存的报价序列和同一个实时执行器，缺少完整时段观测或候选股票不在实际行情覆盖中时拒绝验证。覆盖不足、做 T 时序缺失、有效成交少于 3 笔均拒绝。
5. 候选累计净收益至少高于基线 0.1 个百分点；最大回撤不超过基线加 0.5 个百分点且不超过 10%，才通过。默认自动启用，也可改成人工启用。
6. 每个封存窗口只允许一个候选。下一次需至少 10 个未用于候选验证的新交易日，防止反复试同一验证集。失败、通过和已启用版本都留档；仅后续新计划采用新版本。

这是一项有约束的策略更新机制，不保证提高未来收益。真实大模型服务需要服务端密钥；未配置时规则模拟照常运行，页面明确标注“模型待配置”。自动测试使用标明的合成数据和模型适配器替身，仅验证流程，不冒充真实 AI 或历史收益。

## 模块

`frontend/`：独立浏览器页面与交互。`shared/scoring.js`：纯评分函数。`backend/domain/`：纯交易账本与验证。`backend/services/`：公开行情、反馈、大模型与盘后编排。`backend/storage/`：D1 存储和原子写入。`backend/routes/`：API 方法、输入和跨站写入检查。`drizzle/`：追加式迁移。`scripts/`：本地 D1 适配器与独立重放工具。

密钥仅从服务端环境读取；浏览器构建只依赖前端与共享评分模块。生产继续使用现有私有 Sites 访问边界，不改变分享范围。GitHub 源码仓库可以公开，账户数据库、实际密钥和本地导出不提交。

## 选股排序与版本

新版新建仓按策略精确分（六位比较精度）、信号日成交额、股票代码依次排序；交易阈值仍使用整数分。计划可展开查看候选排序和选择原因。排序版本、输入及摘要随计划冻结，旧计划不重排。已有研究窗口继续原版本，释放窗口后旧主账户自动切换未来新计划；此次规则更新不声称已验证收益改善。详见[精确评分与流动性决胜](design/signal-selection.md)。
