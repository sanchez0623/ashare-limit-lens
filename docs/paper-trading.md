# 模拟交易与收益核验

## 时间与数据

每天北京时间 15:30 的已链接 Sites 任务调用 `POST /api/run-daily`。服务端在 15:05 前不归档、不结算。涨停评分保存当天第一份快照；盘后计划只用于下一实际交易日。执行时检查计划冻结时间早于交易日 09:15，禁止当天收盘评分参与当天成交。

账户首次结算只建立收益基准，不追溯执行已有历史评分。每日行情、计划、成交、权益持久化；行情日期不匹配、持仓价格缺失、昨收与上一账面价格不同或缺少相邻交易日结算时暂停，保留资金和错误状态。除权、分红、送股目前需要核对处理，不能作为普通价差计入收益。系统不补造历史快照。当日评分源缺失但持仓行情可结算时，只生成明确标注的防守计划，停止新增和做 T，保留旧仓止损、止盈与最长持有期保护。

东方财富涨停池决定评分覆盖范围：沪深主板及创业板，排除 ST、科创板与连续一字新股。腾讯日线确认交易日、开收盘价和涨跌停价；分钟行情用于确认盘中交易顺序。公开接口可能限流或停止服务。

## 计划与成交

基准策略：个股评分至少 80、行业板块分至少 55、指标覆盖至少 80%；不追逐 5 板以上、一字特征或高换手样本。最多 4 个持仓。情绪分对应目标仓位 55%、35%、15%，情绪不足 40 时不新增仓位。建仓和加仓在次日 09:30–09:35，包含滑点的买价不得超过事前上限。减仓和清仓使用同一开盘窗口。成交不足保留实际份额，未成交不计费用。

持仓可按照评分延续、目标仓位、盈亏、持有时间生成建仓、加仓、减仓、清仓、正向 T、反向 T 或持有动作。默认止损 6%、分批止盈 12%、最长观察期 5 个结算日。旧仓的事前保护阈值可以在分钟行情上触发；触发后取消未完成的普通计划。新买份额遵守 T+1，不能当天止损卖出。

硬约束：单股买入仓位上限 20%、总买入敞口上限 60%、账户回撤达到 10% 后规划清仓并停止新增仓位；价格波动、跌停和部分成交仍可能使实际风险超过阈值。不透支、不融券；买入 100 股整手。成交采用采样价加 10 bps 滑点，最多参与单分钟成交量的 1%。触及涨停不假设买入，触及跌停不假设卖出。缺少分钟行情时普通订单仅允许明确标记的开盘价假设成交，无法模拟盘口排队。

做 T 必须有可卖旧仓和接近完整、严格递增的分钟序列。正向 T：先在事前低吸线买入，再在更晚时间的兑现线卖出旧仓；反向 T：先卖旧仓，再在更晚的低吸线买回。默认操作底仓的 20%，上下触发线为前收盘的 ±2%。第二腿未成交时保留实际新增或减少的仓位。不能用日线最高、最低价虚构先后顺序。

费用假设：佣金 0.025%、每次模拟成交最低 5 元，过户费双边 0.001%，卖出印花税 0.05%。多分钟保护订单分笔收取费用，是保守的模拟假设。费用与税率冻结在当前引擎中，AI 不能改动。

## 账本与验证

所有资金和价格使用整数分，卖出按 FIFO 释放旧批次成本，买入费用进入成本。账户、当日行情、权益和成交在 D1 原子批次写入，并用账户版本和运行标识防止并发重复成交。

```text
现金 = 初始资金 + 所有成交现金变动
权益 = 现金 + 持仓数量 × 最新收盘价
累计盈亏 = 权益 − 初始资金 = 已实现盈亏 + 浮动盈亏
当日收益率 = 当日权益 / 上一日权益 − 1
累计收益率 = 当前权益 / 初始资金 − 1
```

首次结算日起，以同期上证指数作为基准。页面“核验收益”同时检查现金、费用、盈亏等式、计划和行情 SHA-256 值，并用全部冻结计划及行情重放逐笔成交与每日权益。

下载“完整记录 JSON”后，可脱离网站运行：

```bash
npm ci
npm run verify:paper -- /path/to/limit-lens-paper.json
```

校验失败返回非零退出码。SHA-256 用于发现导出内部数据改变，不是独立第三方签名；自行同时修改数据与哈希不能证明真实性。导出记录包含模拟账户信息，应保存在可信位置。

## AI 自我改进

AI 审计评分仍由冻结评分与下一交易日实况生成；交易策略改进另有版本流程：

1. 积累至少 30 对相邻交易日的评分与行情，使用前 20 日训练、后 10 日封存验证。
2. 大模型只接收训练信号及扣费后的重放表现。验证窗口行情不发送给模型。
3. 严格校验 JSON 参数白名单、类型和区间，禁止执行代码、改动账本或修改硬约束。
4. 基线与候选在同一封存行情、同一起始资金、相同费用和成交条件下重放。覆盖不足、做 T 时序缺失、有效成交少于 3 笔均拒绝。
5. 候选累计净收益至少高于基线 0.1 个百分点；最大回撤不超过基线加 0.5 个百分点且不超过 10%，才通过。默认自动启用，也可改成人工启用。
6. 每个封存窗口只允许一个候选。下一次需至少 10 个未用于候选验证的新交易日，防止反复试同一验证集。失败、通过和已启用版本都留档；仅后续新计划采用新版本。

这是一项有约束的策略更新机制，不保证提高未来收益。真实大模型服务需要服务端密钥；未配置时规则模拟照常运行，页面明确标注“模型待配置”。自动测试使用标明的合成数据和模型适配器替身，仅验证流程，不冒充真实 AI 或历史收益。

## 模块

`frontend/`：独立浏览器页面与交互。`shared/scoring.js`：纯评分函数。`backend/domain/`：纯交易账本与验证。`backend/services/`：公开行情、反馈、大模型与盘后编排。`backend/storage/`：D1 存储和原子写入。`backend/routes/`：API 方法、输入和跨站写入检查。`drizzle/`：追加式迁移。`scripts/`：本地 D1 适配器与独立重放工具。

密钥仅从服务端环境读取；浏览器构建只依赖前端与共享评分模块。生产继续使用现有私有 Sites 访问边界，不改变分享范围。GitHub 源码仓库可以公开，账户数据库、实际密钥和本地导出不提交。
