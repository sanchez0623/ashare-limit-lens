# V5 交易周期归档

本机维护命令将旧主账户、全部影子账户的成交、持仓、净值、会话、计划、反馈和证据报告完整归入不可变历史，再从账户配置的初始资金、空仓开始新周期。共享行情快照、策略版本、不可变输入与研究记录保留；研究次数、样本占用和月度预算不会重置。归档不模拟卖出，不将旧盈亏计入新周期。

```powershell
node scripts/trading-cutover.mjs --date=2026-10-26
node scripts/trading-cutover.mjs --date=2026-10-26 --apply
```

命令使用 `.env` 的 `LOCAL_DATABASE_PATH`，默认 `.sites-runtime/local.sqlite`。第一条预览，第二条执行。执行前以 SQLite 备份 API 保存一致性备份，执行后在 `.sites-runtime/trading-archives/` 输出完整 JSON、成交 CSV、摘要和新周期重放核验结果。该目录不提交 Git。

迁移仅在下一执行日 09:30 前、信号日收盘后进行，拒绝活动研究、过期快照、损坏计划、已开始的执行日会话或准备后变化的账户/输入。归档分块保存原始数据库行，每块及清单均校验 SHA-256；归档和所有账户变更在同一本地事务完成，失败全部回滚。相同执行日重复操作返回已有归档，不再次清空交易。

周一计划使用原 V5 计划的冻结观察名单和历史事实，由空仓账户重新调用原计划构造器；只保留观察候选，不保留旧仓退出、加仓或做 T 指令。原始快照不改写，新的输入另存不可变副本，记录原计划及快照摘要。原盘中影子观察如已登记，会从同样的空仓和观察池重新开始；旧核验结果不会成为新周期通过证据。旧龙头切换状态随原账户归档，新周期明确采用 V5 盘中条件执行。

“模拟交易”顶部提供“历史交易归档”，可以下载旧周期成交 CSV 和完整 JSON。`GET /api/paper/archives` 返回归档清单，`GET /api/paper/archives?id=...` 下载核验后的完整内容，增加 `format=csv` 下载成交。HTTP 接口只读；清空仅由本机维护命令执行。

新周期在配置历史中冻结 `TRADING_CYCLE_STARTED` 期初账户，导出重放从这一边界开始，缺少或篡改该边界会使核验失败。执行日仍由正常交易日历与盘中报价检查决定，缺少行情不会补造成交。

## 新周期改用龙头风险预算

用户选择独立的 `dragon-risk-v1` 时，在新周期尚无成交、持仓、净值或执行会话的情况下，可以执行：

```powershell
node scripts/switch-dragon-cycle.mjs
npm run test:dragon
```

命令先另存数据库备份，沿用最近保存的龙头数值参数，以当前执行版本登记为“人工指定 · 未验证”，再经正常配置检查和整体切换流程启用。旧 V5 未执行计划保留为修订；新主账户与已有独立观察改用龙头政策，现金及期初边界保持不变。全部写入及新计划核验在同一事务中完成，失败回滚。

归档记录中明确指定的下一执行日决定新周期准备截止；期间的周末可以按真实当前时间切换，不能伪造盘前时间。执行日 09:30 起、已有会话或任何成交后拒绝本命令。盘中候选按实际买点优先级、信号日成交额和代码排序，共享风险预算及止损距离决定数量，原综合评分和旧风控不参与。每笔初始 R、加减仓阶段、T+1 和费用仍由同一龙头执行内核管理。

专项测试包括现有龙头配置、资金、R 管理与双向 T 测试，以及周末切换、排序竞争、止损距离仓位、失败回滚和首个交易日结算后完整重放；V5 默认回归范围保持独立。
