# 精确评分与流动性决胜

状态：首版已实施。设计依据：main `1ad8e9d`。新增 `signal-ranking-v2`；20 日成交额中位数与板块集中度约束留待独立版本。

## 排序规则

先筛选满足已有评分、板块、覆盖、风险和价格条件的候选，再按以下顺序分配建仓名额：

1. 策略加权并扣除风险后的精确评分较高。
2. 同分时，有有效信号日成交额者优先，成交额较大者优先。
3. 仍相同时按六位股票代码升序。

`scoreValue = clamp(Σ有效因子值×当前策略权重 / Σ有效因子权重 − deduction)`。`score` 仍按原公式取整，80/88/82 等阈值继续使用整数。`scoreRankKey = round(scoreValue × 1_000_000)` 固定六位比较精度，避免机器浮点微差制造假决胜；不用 epsilon 比较。快照 `rawScore` 不是策略排序输入，归档评分列表不重排，避免改变原有 Top 样本和评分反馈。

成交额使用信号日（执行日前一交易日）的人民币冻结金额，按整数分归一化。非有限数、非数值、零、负数及超出安全整数范围均为未知。未知只在同分时靠后，不压过更高评分。v2 缺失评分或覆盖不新增建仓；v1 保留旧的字段缺失判定，以便重跑原路径。重复股票代码拒绝生成计划。

建仓采用共同目标预算，直接比较成交额与共同预算／成交额的顺序相同。不根据最终现金分配反向重排，也不优待只能买很少的股票。成交额是流动性代理，不保证次日开盘成交容量，不是实测滑点。

## 计划与审计

已有持仓先按原规则生成其他动作，候选随后逐只检查名额、整手、现金和计划敞口。新版建仓预算同时受账户单股、总仓位上限约束；每次入选后累计费用预算和计划敞口。卖出计划不增加可用现金。实际成交仍由原执行引擎检查现金、持仓、T+1、费用、行情及容量。

每份新计划保存完整 `selectionPolicy`、`selectionPolicyDigest`，以及 `selectionAudit`：信号日、快照时间、规范化快照摘要、候选因子输入、风险扣分、资格字段、精确分、比较键、成交额分、排序位置和选择／跳过原因。新版建仓订单还保存精确分、比较键、成交额和 `selectionRank`。

`selectionSnapshotDigest()` 对完整快照规范化后计算 SHA-256：股票按 code、板块按 name 排序，因子数组保留权重位置。列表乱序不改选股摘要，数值、日期及其余快照内容变化都会改摘要；不修改原快照。主账户、影子和回测冻结入口提供该摘要，主账户导出核验再与归档快照独立核对。

“下一交易日计划”显示排序规则、精确分和可展开的选股依据；未入选原因包括已有持仓、资格不足、名额用完或预算不足，不表示股票没有价值。

## 观察池分级（方案 8）

观察池把 skill 中的“重点关注／一般关注／备选观察”量化为 A/B/C 三级，规则版本独立记为 `gradeRulesVersion = 1`，不进入 `selectionPolicy` 与政策摘要：

| 等级 | 规则                                                               |
| ---- | ------------------------------------------------------------------ |
| A    | 评分 ≥ 80 且买点为打板/炸板低吸，且股票分类为连板龙头型            |
| B    | 评分 ≥ 60 且非平庸型，且未被类别上限压低                           |
| C    | 评分 40–59，或波段震荡型（类别封顶 C）                             |
| 剔除 | 评分 < 40 或平庸型；`grade` 为 `null`，附 `gradeReason`             |

评分只决定下限，股票分类决定上限：连板龙头型最高 A、强势反包型最高 B、波段震荡型最高 C、未分类（`stockClass` 为 `null` 或未知）最高 B。A 级还要求买点命中打板或炸板低吸（优先读 `buyPoint.labels`，缺失时回退 `buyPoint.primary.type`），未命中降为 B。阈值使用整数 `score`，与既有 80/88/82 口径一致。

分级在排序之后注解，不改变 `rankSignals` 的排名、不改变建仓资格判断，也不写入订单或执行语义。`selectionAudit.candidates` 保存 `grade` / `gradeReason`，审计根保存 `gradeRulesVersion`；旧计划没有这些字段仍按原规则有效，前端显示“未分级”。`grade = null` 只表示剔除观察池，信号仍保留用于持仓风控。

## 版本与历史兼容

| 版本                | 排序                                          | 使用方式                                             |
| ------------------- | --------------------------------------------- | ---------------------------------------------------- |
| `signal-ranking-v1` | 整数 score 降序 → code 升序                   | 无标记历史账户、计划、研究清单的兼容解释；可显式重跑 |
| `signal-ranking-v2` | 六位精确分键降序 → 有效成交额降序 → code 升序 | 新账户、升级后的新计划                               |

两个版本的政策内容和 SHA-256 摘要固定；未知版本、同编号改内容、政策字段缺一半或摘要不符均拒绝。日线执行、开会话和后续帧也核验，保存的订单不会因部署重排。

旧主账户没有 `selectionPolicyVersion` 时在初始化入口升级一次。账户 revision CAS 和 SQL `NOT EXISTS research_window_owners(namespace='main')` 同时保护；活动窗口期间保持 v1，释放后下次初始化升级。升级和配置审计原子写入，现金、持仓、旧计划不修改。显式版本的影子账户及连续固定基线不自动升级。

费用或资金调整按既有规则重冻当日尚未执行的计划时，保留被替换计划的选股版本。原报告保留；重新生成历史路径须显式选择 v1，不能把新规则重跑收益冒充原报告。

## 回测与研究接线

`POST /api/backtests` 支持可选 `selectionPolicyVersion`，缺省 v2；运行 `initialBook`、覆盖报告和每份计划冻结政策与摘要。重跑旧版本示例：

```json
{
  "datasetId": "hds-example",
  "initialCapital": 1000000,
  "selectionPolicyVersion": "signal-ranking-v1"
}
```

`replayStrategy(..., options)` 和 `validateCandidate(..., options)` 支持 `options.selectionPolicy`。有期初账本时缺省沿用账本版本，没有期初账本的新重放缺省 v2。候选与对照共用政策；成本压力重放绑定当前账户政策。

单候选、冷启动、赛马在预留和提案清单登记政策；AI 训练绩效按该政策重放。预留后再次核对账户，拦截“读旧账户后、领取窗口前发生升级”的竞态。恢复验证、捕获影子起点和晋级都核验版本；AI 参数白名单不允许改政策。

新版赛马还核验候选及两个匹配对照每个执行日的实际冻结计划和内容摘要。缺计划属于覆盖不足，保留 `INCONCLUSIVE`；实际混用政策或篡改摘要属于 `INVALIDATED`。晋级入口再次核验，不只相信报告。无标记旧窗口保留历史兼容，不追溯要求当时未记录的新元数据。

## 验收

回归覆盖：真并列、整数展示并列、权重／扣分／缺因子、整数阈值、六位精度、非法成交额、代码兜底、乱序、资金／仓位约束、主／影子一致、重复冻结、活动旧窗口、升级领取竞态、重冻兼容、政策篡改和研究版本检查。

另模拟三轮完整建仓清仓，用保存订单独立回放账本、费用及净值；修改归档成交额后核验失败。历史 v1/v2 对比用于解释换股、成交、成本和收益变化，不宣称统计优势；改善仍需事前冻结的新数据验证。

后续成交额中位数需要完整可追溯、同口径且无未来信息的历史输入；板块集中度属于组合约束。二者分别版本化，本次不引入。
