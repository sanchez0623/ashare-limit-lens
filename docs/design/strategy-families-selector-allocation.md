# 策略家族、情绪选择器与共享资金分配

本功能扩展 [策略赛马 §4.2–4.3](multi-strategy-tournament.md)：策略先在固定训练与测试窗口冻结，再用新的前瞻日期、两个匹配对照、全历史尝试序号和成本压力闸门研究。新增程序不会直接替换正在运行的策略。

## 使用

策略赛马页的「研究范围」可选择六因子数值微调、AI 家族与组合、固定家族模板、固定情绪选择器或固定共享分配。发起时先保存新政策，再预留整个候选批次。存在活动窗口时不能改政策。三个模板模式无需模型密钥，同样占用预算和全部候选尝试序号；无变化、重复、错误和历史未通过的成员保留记录。模板不根据测试收益替换。

新版政策为 `version: 2`、`strategySpaceVersion: "strategy-space-v2"`，`generationMode` 为 `AI/FAMILIES/SELECTORS/ALLOCATIONS`。原 `version: 1` 只允许数值小步变化。API 仍使用 `POST /api/strategies/policy` 和 `POST /api/strategies/cohorts`；状态响应包含完整政策与策略空间。族规则及实际执行源码摘要事前冻结；源码不匹配的旧研究需以新日期重建，不能借用旧报告启用。

## 家族和参数

| 家族                  | 信号日条件                                            |
| --------------------- | ----------------------------------------------------- |
| `limit-momentum-v1`   | 原六因子评分、板块、覆盖及风险筛选                    |
| `first-board-v1`      | 已知连续板数为 1                                      |
| `relay-board-v1`      | 已知连续板数为 2–4                                    |
| `sector-resonance-v1` | 板块分至少 65，同一板块至少 3 只已知涨停股            |
| `low-turnover-v1`     | 已知换手率 1%–8%                                      |
| `cash-v1`             | 停止新开仓、加仓与做 T，保留风险退出与必要的旧 T 恢复 |

新增程序位于策略参数的 `program` 字段，版本为 1。单家族含 `kind: "FAMILY"` 及 `family: {familyId, familyVersion: 1}`。情绪选择器含 `kind: "EMOTION_SELECTOR"` 及 `regimes: {high, mid, low}` 三个家族引用，阈值沿用共同的 `exposureTiers`。共享分配含 `kind: "ALLOCATION"` 和 2–4 个 `components`，每项有唯一 `id`、`weightBps` 和家族引用；权重以 500 bps 为步长、合计 10000，成员按 id 排序。字段集合固定，不接受表达式、任意代码、子账户资金、费用或风控覆盖。

连续板数优先读取独立的 `consecutiveBoards`；该字段明确为空时不回退。旧六因子快照的 `height` 按其已发布的连续板数语义兼容。「几天几板」不能代替连续板数。换手率空值不当零。各家族继续受公共六因子门槛及风险限制，缺必要字段时不入选。

程序变更算一个逻辑参数组，继续受原数值参数步长与组数上限约束。默认六因子与显式程序区分登记；手动交易设置只修改数值参数，保留已验证程序。换家族、选择器映射或分配权重通过研究批次验证后启用。离散参数距离固定为 1，加上原数值距离，避免事后改排序。

## 持仓、资金与实际成交

家族负责新增需求，共用同一组数值风险、退出和做 T 参数；选择器切换时不清零现金、不重置持仓或风险峰值。低情绪和未知情绪停止新增交易。计划保存信号日情绪、选择结果、原快照摘要和各成员额度；快照必须在计划冻结前可用，候选必须先冻结再捕获前瞻起点。

分配器只使用一个真实账本。新开仓需求按固定权重分配，扣除已归属持仓；未归属旧仓按权重预留额度，未用额度留现金。同股需求合并为一张订单，最大持仓数按股票去重，总现金、单股风险、总敞口和同股区间成交容量统一检查。退出、保护单和双向 T 使用公共管理器，保护退出优先；不会为每个成员复制现金或容量。做 T 按共享账户风险限制执行，分配权重约束常规新增额度，不把成员解释成独立资金账户。

实际成交按冻结成员 id 顺序消耗需求，按真实成交数量分摊费用，余分给最后一个实际成交成员；费用和数量合计必须与主成交一致。部分成交、重试和重启保留已消费份额。持仓 lots 记录数量归属，卖出只消耗 T+1 可卖 lots；旧仓归属标为继承。组合净值由唯一真实账本计算，不拼接家族净值或把成员收益相加。

## 核验

迁移 `0021_strategy_signal_snapshots.sql` 按内容摘要独立保留不可改写的原信号快照，所有计划共享一次存储。展示归档后续重算不替换已有计划的输入；财务导出的 `signalSnapshots` 支持离线核验，压力测试也使用同一冻结原快照。去除程序声明伪装成旧策略、重写成员参数及同步修改摘要，仍需与登记版本和冻结提案匹配。

执行前按信号日原始快照重新生成程序计划，独立核对家族、情绪和额度。正式评估重新核对冻结政策、候选 patch、家族及策略空间；启用还核对前瞻会话与实际原快照，并以账户 revision、策略参数和两类政策 ID 做原子提交。压力导出的原始输入包含完整策略程序，既有 `verify:execution-evidence` 重放所有成本情景；财务 `verify:paper` 同时重算程序计划。

回归包含三个模式的完整合成前瞻闭环、期间情绪切换、旧持仓承接、共享容量、费用守恒、恢复幂等，以及字段注入、重复成员、非法权重、未来快照、重写选择声明与资金上限。合成案例验证流程和核验能力，不用于推断真实市场收益。
