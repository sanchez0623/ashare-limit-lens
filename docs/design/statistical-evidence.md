## 2. 统计设计依据

时间序列区块重采样用于保留短期依赖；其有效性依赖弱依赖、相对稳定等条件，不能仅因为跑了很多次 bootstrap 就宣称结论可靠。[Politis–Romano 原始论文](https://www.tandfonline.com/doi/abs/10.1080/01621459.1994.10476870)。首期复用仓库已有固定长度循环区块算法，不把它误称为随机区块长度的 stationary bootstrap。

同时检验多个候选/指标会产生选择问题，多重检验方法应保留联合依赖并明确控制对象。[Romano–Wolf 原始论文](https://doi.org/10.1111/j.1468-0262.2005.00615.x)。首期诊断使用简单可审计的当日检验族 Holm 校正；正式赛马保留全历史尝试预算，不在本任务偷偷换成复杂的 stepdown 模型。

普通区间与 p 值不能保证“持续查看直到显著”后的决策有效；序贯方法需要另外的假设和设计。[Johari 等原始论文](https://arxiv.org/abs/1512.04922)。首期把每日滚动证据明确标为探索诊断，自动启用只读取固定终点前瞻报告；不能把普通滚动区间包装成 anytime-valid 置信序列。

## 3. 三类统计对象及口径

### 3.1 个股评分质量

每个结果日 t 使用上一交易日已经冻结的样本、评分和前 20% 组成员：

```text
IC_t = Spearman(昨日评分, 昨收至今日收盘观察收益)
E_t  = 今日有效前20%组平均观察收益 - 今日完整有效样本平均观察收益
```

IC 的范围 [-1,1]；收益内核为小数，例如 0.003=0.3 个百分点=30bps。Top 组从原冻结排序确定，不根据今日收益重新挑选，不把失踪高分股用其他股票补齐。前组包含在全组中，两者有相关性，不能分别当成独立样本检验。

单日 IC/E 是该日已观察样本的描述值；不通过“对股票独立重采样”给它附上看似精确的 95% 区间。同一板块股票和共同市场冲击存在依赖，且冻结涨停池通常是当日目标集合而非随机抽样。

首期估计对象为**按交易日等权的平均 IC 和平均观察超额**：`mean(IC_t)`、`mean(E_t)`。这回答评分在一段时间里是否有持续方向性，不把 60 日的股票行合并成几千个独立样本，也不按当日涨停家数对市场日加权。小池和大池的样本质量单独显示。

### 3.2 板块评分质量

用事前冻结板块归属和成员，计算板块评分与各板块平均观察收益的每日秩相关，再对日期序列计算区间。多概念归属要使用冻结的主板块或明确的分摊规则，不能让一只股票被重复计为多个独立样本。

建议第一批先实现个股两个主指标；板块聚合 IC/E 及逐板块细分作为第二批，使用独立声明的次要检验族。板块不足、样本过小或归属变化时返回原因；不能对每个板块各给一个未经校正的“显著成功”标签。

### 3.3 模拟交易质量

账户日收益从完整持久净值计算：`r_t = equity_t / equity_(t-1) - 1`；窗口首日相对捕获期初权益。现金日、无成交日照常保留，不能只统计赚钱或发生交易的日期。

针对匹配父策略与匹配固定基线，配对日差使用已有对数口径：

```text
d_t(parent)   = log(1+r_t(candidate)) - log(1+r_t(parent))
d_t(baseline) = log(1+r_t(candidate)) - log(1+r_t(baseline))
```

对照必须具有相同期初现金/持仓、日历、显性费用、成交成本模型与输入质量。指数收益可以作为另一个背景曲线，不能代替匹配对照。没有同口径对照，返回 `NO_COMPARABLE_BASELINE`，不得把未知对照当作零收益。

UI 同时显示真实窗口累计净收益差的点值和“平均每日对数收益差”的区间。累计简单收益差、相对财富比和日对数差不是同一个量，必须分别命名；不能把日均区间直接乘 60 后冒充已实现累计收益的置信区间。

主账户连续账本包含实际策略切换，衡量的是持续系统的结果；单一当前策略的证据取其冻结 cohort。不能把每轮胜者的最优窗口拼接成主账户收益，也不能把混合策略区间标为某个新版本的成绩。

## 4. 默认政策与证据状态

新增 `EvidencePolicy`，独立于评分权重和 AI 参数；参数在数据到来前版本化。初始建议：

| 字段                              | 默认                    | 约束/说明                                                         |
| --------------------------------- | ----------------------- | ----------------------------------------------------------------- |
| `windows`                         | [20,60,120]             | 交易日，不是自然日；60 为主视图，20 为短窗诊断                    |
| `primaryWindow`                   | 60                      | 不根据哪一档显著自动切主视图                                      |
| `confidenceLevel`                 | 0.95                    | 滚动诊断为双侧、单窗口名义覆盖                                    |
| `blockLength`                     | 5                       | 首期与现有算法一致；区块长度敏感性预登记 [3,5,10]，只做稳健性附表 |
| `resamples`                       | 10000                   | 日常诊断；正式极小 α 继续使用现有额度规则                         |
| `minValidDays`                    | 20                      | 少于 20 日只展示点值和样本不足                                    |
| `minWindowCoverage`               | 0.90                    | 对预声明的窗口日历，不以成功记录数补满窗口                        |
| `minStockCoverage`                | 0.90                    | 单日进入新诊断序列的质量要求；旧单日分数仍按旧口径保留            |
| `minValidStocks` / `minTopStocks` | 10 / 3                  | 继承单日最低数量，不能把数量多视为独立天数多                      |
| `maxDegenerateResampleRatio`      | 0.05                    | 退化重采样过多时不输出可靠区间                                    |
| `multiplicityMethod`              | HOLM_WITHIN_ASOF_FAMILY | 只校正同一截止日、事前固定指标族，不宣称校正无限次查看            |
| `purpose`                         | DIAGNOSTIC              | 滚动报告固定无启用资格                                            |

样本状态与统计方向分开返回：`PENDING / INSUFFICIENT_SAMPLE / INCOMPLETE_DATA / MIXED_CONTEXT / DEGENERATE / READY`。READY 时方向用 `POSITIVE / INCLUDES_ZERO / NEGATIVE`；再附 `SHORT_WINDOW`、`EXPLORATORY_REPEATED_LOOKS`、`COST_PRIOR_UNCALIBRATED` 等标签。

“区间跨零”表示目前证据不足，不等于策略无效；“区间完全为正”也不代表下个交易日赚钱概率为 95%。20 日即使能计算区间，也显示短样本标签，不作为正式前瞻验收替代品。

## 5. 时间窗口、数据质量与防止混用

### 5.1 固定日历与缺口

每份报告冻结截止日以前的最后 H 个真实交易日及源数据可用时点。行情/评分/净值缺失的日期留在窗口里；不向前或向后多取几天凑满 H 个成功记录，不插值股票收益、不将未获取行情当作 0。

保存 `expectedDates/validDates/missingDates/exclusionReasons`。纯现金、已经完整结算的 0 收益日有效；采集失败的 0 无效。次日补到的数据产生新的输入修订版，保留原报告，不悄悄覆盖先前“截至当时”的证据。

缺口将序列分成连续片段。区块从有效连续片段中生成，不能压缩日历后把缺口两边拼为相邻交易日；输出跨片段重组假设。片段太短、可用区块不足时返回 INCOMPLETE_DATA。完整窗口可直接复用现有循环区块矩阵。

初版缺口模式固定为“各连续片段内循环区块重采样，保留片段原长度，再按原天数合并均值”；每个参与片段至少达到冻结区块长度，出现过短片段就不输出区间，避免自行丢掉不利日期。报告另标 `CONDITIONAL_ON_OBSERVED_DAYS`：缺失可能与行情状态相关，该区间不能修复非随机缺失，也不代表完整市场日历的无偏效果。

### 5.2 一致的评分与执行上下文

评分上下文摘要包括评分算法、权重、冻结池/Top 定义、板块归属规则和收益口径。仅 `modelVersion=rules-v1` 不足以区分不同权重。默认稳定评分证据按相同摘要计算，变更导致新证据 epoch；跨 epoch 的持续系统诊断只能另行明确标记 MIXED_CONTEXT，不能给“当前评分有效”结论。

交易证据摘要另包括账户/对照、期初快照、策略 lineage、手续费、开盘成本、采样/延迟、引擎版本及日净值完整性。当前窗口末日数据从已结算净值取，不能从下一日已经推进的账本取。

历史冷启动的 reconstructed/historical 数据、真实事前评分 live 数据、research namespace 数据分别报告。可以复用统计内核，不能合并成一条“已经实测 120 天”的序列。股票停牌、除权、行情缺失的剔除统计必须公开，提醒观察结果以已核验样本为条件。

### 5.3 与 AI 血缘的关系

诊断计算自身不消耗新的候选比较 k，也不抢正式日期 claim；它只是读取既有结果。但 AI 用某份诊断调整策略时，必须登记读取的日期与用途，这些已经看过的结果不能再充当该候选的新测试数据。

活动 cohort 的参数、窗口与验收政策不因滚动图而改变。未完成正式窗口的结果不得反馈给 AI 用来修改同一候选；人工看到诊断后另建候选也要登记新尝试和未来未使用测试日期。遵循既有 [walk-forward 方案](ai-strategy-walk-forward.md) 与 [赛马方案](multi-strategy-tournament.md)。

## 6. 区间和 p 值的确定性计算

### 6.1 重采样单位

先从每个日期生成指标向量，例如 `[IC_t,E_t,d_parent_t,d_baseline_t]`，每次抽样共享日期区块索引。完整日期面板的相关股票、两个对照和同日指标一起保留。不同报告使用自己的冻结样本，但同一比较族不能为每个成员重新挑种子。

随机种子由 `namespace/purpose/asOf/orderedWindowDates/inputDigest/policyDigest/methodVersion` 的规范化摘要生成；禁止重新运行直到结果显著。计算为纯函数，输入矩阵、方法版本和种子可导出。

### 6.2 诊断双侧区间

对于某个日序列 x，观察均值为 θ̂。区块重采样得到 θ*，误差分布 `e*=θ\*−θ̂`，使用事前指定的 basic bootstrap：

```text
CI_95 = [ θ̂ - Q_0.975(e*), θ̂ - Q_0.025(e*) ]
```

报告同时保存标准误估计、观察均值、原始分位数、B、区块长度与有效样本日数。IC 的参数支持域可与 [-1,1] 取交集，必须保留未限制区间以便核验。不能以“bootstrap 正收益占比”宣称是真实盈利概率。

平均 IC 使用每日 IC 序列，不能直接用 Pearson/Fisher 的独立正态相关公式给日秩相关套区间。逐板块指标和收益差沿用同一日期单位；极端收益不偷偷删除或 winsorize，敏感性处理另存方法并冻结。

### 6.3 明确零假设的 p 值

双侧诊断默认 H0: μ=0。构造 `x0_t=x_t−θ̂` 的零假设序列，以同一合法区块机制得到 θ0\*：

```text
p_two_sided = (1 + count(|θ0*| >= |θ̂|)) / (B + 1)
```

若事前声明正向单侧 H0: μ≤0，则使用边界 μ=0，`p_one_sided=(1+count(θ0*>=θ̂))/(B+1)`。方向不能见到负均值后翻转。不能把未居中的普通 bootstrap 中“均值≤0的比例”直接命名为已校准 p 值。

现有 `pairedLowerBoundTest` 计算的是单侧 percentile 下界，并未提供常规 p 值。正式赛马页面先如实展示该下界、观察均值、α 和方法名，不凭空补造一个 p。新版诊断 basic 区间与旧 percentile 闸门使用不同 methodVersion，明确记录，不混为同一种估计。

输入非有限、收益≤−100%、全常数/零方差、全部相同秩、有效区块不足时返回退化/证据不足，不能生成 p=0 或零宽度区间后自动判优。计算额度不足不放宽置信级别。

### 6.4 当日多指标校正

评分主检验族固定为 60 日平均 IC 与平均观察超额两个指标；账户诊断的两个对照为另一个明示族；板块细分为单独次要族。窗口 20/120 为辅助视图，首期只展示区间和 raw p，不给自动正式成功状态。

对一族 m 个预登记 p 升序排列：`p_adj(i)=min(1,max_(j≤i)[(m-j+1)×p_(j)])`，再映射回原指标。样本不足的指标保留族大小，不能删除不显著指标后减少校正项。若产品要表达跨所有族的总体结论，另分配总体预算，不能把几个各 5% 的族称为统一 5%。

不可估计的检验在内部排序中按 p=1 保留名额，外部字段仍返回 null 与证据不足原因，不对它发布“p=1 已证明无效”的结论。

区间是名义单指标区间，Holm p 是当日族校正 p，页面分别标记；不能把普通 95% 区间说成同步多指标置信带。未来同步带/stepdown 是新方法版本，需模拟验收。

## 7. 每日滚动、反复查看与正式启用

### 7.1 每日诊断确实运行，但不触发晋级

每个收盘日生成 20/60/120 日证据与滚动趋势图。近 60 日与昨天近 60 日有 59 天重叠；连续三天正向也不是三次独立验证。报告必须有：`purpose=DIAGNOSTIC`、`eligibleForPromotion=false`、`repeatedLooksAdjusted=false`。

例如“ρ均值0.12，95%区间[−0.03,0.25]，60个市场日；暂不足以确认正向关联”。这些数字是界面示例，不来自当前账户。若区间为正，使用“该窗口出现正向统计证据（探索诊断）”，同时显示未校正重复查看。

### 7.2 正式前瞻报告

正式报告只能从预登记 cohort/experiment 的固定终点生成；沿用尝试序号 k、`alpha_k=0.05/[k(k+1)]` 及两个对照的预算。不能用今天刚挑出的显著滚动窗口替换原 30/60/90 日窗口，也不能在第 20 日提前宣布通过。

把目的、窗口、尝试预算、冻结政策和执行成本指纹绑定到正式报告摘要，统一晋级入口拒绝 DIAGNOSTIC 报告，包括人工/API 重试。未完成原窗口、完整日登记缺失、成本/算法指纹变化、覆盖不足和计算预算不足均不晋级。

现有正式下界检验保留到显式版本迁移；未来切换至中心化/学生化统计时，用新政策和新候选窗口，保留旧报告及 verifier，不能用更有利的方法追认旧候选。

### 7.3 后续序贯能力

如果以后要求“随时看到足够证据就可以提前启用”，另立序贯方案：预声明观察次数的 group-sequential/alpha-spending，或在收益界限及依赖条件成立时的置信序列/e-process。每日依赖、重叠持仓和市场非平稳不能被 IID A/B 假设自动覆盖。本期不提供 anytime-valid 自动提前启用。

## 8. 架构、数据结构与任务流程

### 8.1 模块职责

| 文件                                                  | 职责                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------ |
| `backend/domain/review-metrics.js`（新增）            | 秩相关、冻结 Top 分组、日指标和单位转换；无数据库/网络依赖         |
| `backend/domain/research-statistics.js`（扩展）       | 共用 PRNG/索引、合法区块、区间、零假设 p、Holm；保留旧正式方法版本 |
| `backend/domain/evidence-policy.js`（新增）           | 用途、窗口、质量、方法和指标族的严格校验                           |
| `backend/services/evidence.js`（新增）                | 读取来源、冻结输入、计算编排、报告 DTO                             |
| `backend/storage/evidence.js`（新增）                 | 政策、每日指标、不可变报告和输入 manifest                          |
| `review.js` / `paper.js` / `strategy-tournament.js`   | 来源提交后登记待计算任务与证据引用，不同步跑大计算                 |
| `promotion.js` / `research.js`                        | 校验正式用途/冻结版本、记录 AI 读取用途，不从滚动 p 自动启用       |
| `scripts/evidence-worker.mjs`（新增）                 | 独立统计 worker，复用既有任务租约/分片/CAS 语义                    |
| `frontend/research.js` / `paper.js` / `strategies.js` | 渲染 DTO、单位、区间和原因，不计算 p，不持有 AI 密钥               |
| `scripts/verify-evidence.mjs`（新增）                 | 从导出输入重算指标、统计、摘要及用途限制                           |

不要为每个指标复制一个随机数生成器或 bootstrap 模块；新函数与现有 `resampleIndexMatrix/dailyReturns` 共享基础设施，methodVersion 负责区分语义。

建议函数契约：

```js
computeDailyReviewMetrics({ frozenSnapshot, verifiedOutcomes, policy });
// → { date, contextDigest, values, quality, exclusionReasons }
buildEvidenceWindow({ expectedDates, dailyMetrics, horizon, contextDigest });
// → { expectedDates, validDates, segments, alignedVectors, coverage }
bootstrapMeanEvidence({ values, indexMatrix, confidenceLevel, nullMean, side });
// → { estimate, ci, pRaw, standardError, status, reasons }
adjustEvidenceFamily({ declaredHypotheses, results, method: "HOLM" });
// → 保留所有预登记假设和原族大小的 pAdjustedWithinFamily
publishEvidenceReport({ manifest, statistics, quality, purpose });
verifyEvidenceBundle({ manifest, inputs, policy, report });
// → 核验摘要、日期、纯指标、索引/种子、统计结果和用途限制
```

输入参数全部显式、结果使用 null 表示不可估计。`buildEvidenceWindow` 无权向窗口外寻找补位日期；`bootstrapMeanEvidence` 不读实时数据库或当前设置；发布函数无权把诊断结果改为正式报告。相同数据下不同区块长度/政策是不同 input/policy key，不能覆盖原证据。

### 8.2 持久化

新增迁移及 schema，最小表集：

```text
evidence_policies
  id, version, payload, digest, effective_from, created_at
evidence_daily_metrics
  namespace, series_id, outcome_date, context_digest,
  source_digest, payload, digest, created_at
evidence_reports
  id, namespace, series_id, as_of, horizon, purpose,
  input_digest, policy_digest, method_version,
  payload, digest, created_at
evidence_report_inputs
  report_id, ordered_dates, source_refs, source_digests, manifest_digest
```

同输入/政策/方法唯一发布；输入修订生成新报告 id，原证据不覆写。正式报告可引用现有 cohort 报告而不重复存全部输入，但导出必须带引用内容及摘要，不能只带不可访问的数据库主键。

复用既有研究任务调度增加 `EVIDENCE_DIAGNOSTIC/EVIDENCE_VERIFY` 任务类型。统计读取/计算在事务外；发布报告、任务 DONE 及输出摘要在短的、带 owner/round 的提交中完成。过期 worker 不得发布迟到结果或覆盖新输入版本。

### 8.3 盘后与恢复

```text
冻结评分和次日结果 / 完整主账户及对照结算
  → 确认源摘要和数据可用截止时点
  → 生成每日指标与冻结窗口 manifest
  → 幂等入队统计任务
  → worker 分批区块计算
  → 发布不可变报告与摘要
  → 页面读取；AI 读取经授权的已完成证据摘要
```

任务发现器定期扫描已提交来源与未发布的报告，弥补“源已提交、入队前退出”；不能依赖交易 runner 的 `dailyDate` 成功标记一定包含统计成功。部分来源未就绪时显示 PENDING，源数据不完整时产出明确证据不足报告，不阻塞交易/止损。

统计/AI 不放进 10 秒轮询。SQLite 单写约束下采用短事务，worker 限制 CPU 与分片；Windows 同机进程和容器都使用既有启动流程扩展，不另建常驻前端计算器。

### 8.4 API 与 DTO

建议新增：`GET /api/evidence?series=...&asOf=...&horizon=60`、`GET /api/evidence/history?series=...`、`GET /api/evidence/export?id=...`、`POST /api/evidence/recompute`。GET 只读；recompute 只重算同一冻结诊断输入，不重开正式比较或换种子。写操作沿用现有身份、origin、method、参数校验。

关键 DTO：

```json
{
  "purpose": "DIAGNOSTIC",
  "eligibleForPromotion": false,
  "asOf": "2026-10-09",
  "horizon": 60,
  "status": "READY",
  "metric": "MEAN_DAILY_IC",
  "unit": "CORRELATION",
  "estimate": 0.12,
  "ci": { "level": 0.95, "lower": -0.03, "upper": 0.25, "scope": "POINTWISE" },
  "pRaw": 0.16,
  "pAdjustedWithinFamily": 0.24,
  "repeatedLooksAdjusted": false,
  "validDays": 60,
  "expectedDays": 60,
  "method": {
    "version": "DIAGNOSTIC_BASIC_BLOCK_V1",
    "blockLength": 5,
    "resamples": 10000
  },
  "inputDigest": "example-digest",
  "policyDigest": "example-policy-digest"
}
```

以上是结构示例，实际 p 与区间必须由同份输入计算。缺失值使用 null，不能序列化 NaN，也不能将 null 格式化为 0。历史响应继续提供原单日字段，新 evidence 作为独立引用，避免改写旧评分。

## 9. 页面和 AI 的呈现规则

复盘页保留单日指标，新增默认 60 日证据卡：均值、95% 区间、零线、有效/应有天数、覆盖和方法。20/120 切换提示短窗/辅助视图；滚动置信带注明逐时点区间，不是整条曲线同时覆盖的保证。

账户页分别展示模拟累计净收益、相对匹配对照的点值和日均差区间；附执行成本模型及校准等级。赛马页展示两个对照的正式单侧下界、实际 α、k/预算、完整窗口和晋级闸门原因，不只画一个绿色“统计通过”。

UI 原有“AI 较高置信度”改为“AI 主观把握”，统计区间另列；规则反馈分也不转成概率。AI 输入新增用途、CI、样本/覆盖、调整范围、成本等级和未通过原因；数值由后端冻结，模型只能解释和建议。

正式判断文案由后端结构化证据状态生成，AI 不能覆盖：不能把跨零区间写成“已证明有效”，不能把 `p=0.03` 解释成“97% 概率赚钱”，不能从诊断报告改写策略或研究政策。模型失败不影响客观证据发布。

## 10. 独立核验与验收标准

| 测试                                        | 验收要求                                                 |
| ------------------------------------------- | -------------------------------------------------------- |
| 并列分数、常数分数、常数收益、极少股票      | 平均秩正确；退化返回原因，不能虚构相关或 p=0             |
| Top 身份冻结、高分股停牌/缺失               | 不重选 Top；覆盖和剔除原因完整                           |
| 单位：0.003/0.3pp/30bps                     | 接口与前端一致，不能多乘/少乘 100                        |
| 同一输入/方法/种子重复计算                  | 索引、区间、p、报告摘要一致                              |
| 两个相关对照、同日多指标                    | 共用日期索引，不拆开配对；Holm 映射与族大小正确          |
| 日期缺口、历史混入 live、权重/费用/成本变更 | 固定日历不补长；跨缺口不伪相邻；上下文失配明确显示       |
| 窗口首日净值/期末恢复                       | 从捕获期初和冻结末日结算值计算，次日污染不改变证据       |
| 零假设中心化与退化                          | p 与预声明方向一致，至少为 1/(B+1)；非有限输入拒绝       |
| 真实无交易现金日                            | 保留 0 收益；获取失败不会变成有效 0                      |
| 滚动一次显著、多个重叠窗口显著              | 所有诊断始终无晋级资格，人工/API 不能绕过                |
| 活动窗口读到诊断后 AI/人工修改              | 原候选不能改；新尝试登记，已见日期不能冒充新测试         |
| 来源提交后退出、任务租约过期/重复运行       | 可发现未入队任务，至多发布一次；迟到 worker 不污染新报告 |
| 导出篡改源摘要、日期、政策、方法或区间      | `verify:evidence` 拒绝，正常导出能独立重算               |

统计方法上线前另外运行独立模拟验证，不只测试某个固定例子“显著/不显著”：

- 固定公开种子与不少于 1000 条模拟序列，覆盖独立噪声、AR(1)、波动聚集、厚尾、共同板块因子和已知正/零效应；记录长度 20/60/120 下的覆盖率、I 类错误和检验力。
- 与独立实现/计算器核对 basic 区间、居中零假设 p 和 Holm，不能只用生产函数生成测试答案。为重复查看模拟展示“曾显著”率，确认产品没有误声称控制它。
- IID/弱依赖基准下预登记诊断阈值：95% 区间经验覆盖至少 90%，零效应拒绝率至多 7%；同时给出 Monte Carlo 二项区间。阈值是工程准入要求，不是理论保证。正式检验按其实际 α 和方法另外验证，不能用 5% 诊断测试代替极小 α 验收。
- 若依赖/非平稳情景明显失准，输出方法限制并降为探索用途；不得通过挑种子、事后换区块长度或隐藏失败情景“验收通过”。

这些方法验证数据为合成研究样本，不消耗真实前瞻 claim。性能验收记录目标 Windows 机器上三个窗口的耗时和 worker CPU/内存，交易轮询不等待统计结果；百万级正式重采样继续遵守已有额度和分片要求。

极小 α 的模拟次数必须根据二项误差和目标精度另算；1000 条序列没有假阳性不能证明 10⁻⁶ 级错误控制。算力不足就注明未完成该级别的外部校准，不将日常诊断的模拟结果用于宣称正式方法的精确概率保证。

## 11. 实施批次与关闭条件

1. **批次 A：口径与可核验日序列。** 提取纯评分指标、上下文摘要、日历/缺口、来源隔离、每日指标存储及单位验证；保留既有 review 和账本。
2. **批次 B：滚动证据。** 共用区块内核、basic CI、居中 p、当日族校正、任务/恢复、API 和复盘/账户展示。完成独立方法模拟及导出 verifier。
3. **批次 C：正式证据呈现与成本联动。** 展示现有赛马单侧下界/预算，绑定执行成本，所有晋级入口拒绝诊断报告，AI 输入和血缘登记同步；板块证据及次要族进入本批。

P0 关闭要求 A–C 与配套成交成本方案的研究接口共同验收：单日不再被呈现为策略有效证明；滚动报告能重算、能解释不确定性、不能用于提前晋级；正式候选同时满足冻结窗口、成本、经济效果及统计闸门。后续 anytime-valid/同步置信带另立新版本，不阻碍这一阶段落地。

建议联合交付顺序：先实施成本批次 A 与本方案批次 A，使执行口径和可核验日序列稳定；再完成两侧数据质量/诊断批次；最后一起验收压力经济闸门、正式证据呈现与所有晋级入口。成本口径变更后旧窗口收益的统计显著性不能直接迁移到新窗口。
