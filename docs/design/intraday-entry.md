# 盘中条件执行 v1

V5 选股政策保持原内容。新增 `intraday-entry-v1` 执行规则：盘前冻结候选历史、准入规则、预算公式和各买点窗口，盘中按已经观察到的事实派生订单。未标记的旧计划继续使用原执行方式。

## 买点与时间

| 买点                   | 北京时间窗口                    | 说明                                                               |
| ---------------------- | ------------------------------- | ------------------------------------------------------------------ |
| 竞价低吸、假阴跌停低吸 | 09:30—10:00                     | 同花顺竞价终态与当天腾讯开盘价、昨收交叉核对，开盘后确认企稳       |
| 打板                   | 09:30—10:30；13:00—14:30 仅回封 | 实际触板触发，封死涨停不假设排队成交；可成交盘口与成本约束必须通过 |
| 炸板低吸               | 09:30—11:30、13:00—14:55        | 当天触板后的 3%—7% 回撤                                            |
| 首阴                   | 14:30—14:55                     | 当前实体阴线、跌幅和动态 MA5 预确认；不得使用最终收盘价倒推        |
| 尾盘跳水               | 14:30—14:55                     | 仅从 14:30 后的实际采样路径计算 3%—5% 跳水                         |

所有低吸需要连续两次有效报价、价格不再下降和有效的增量成交量。断流、重启后的第一条报价只建立基线。同股一天只新建仓一次，部分成交可以完成原单；不同买点共享现金、仓位和成交容量，不追加普通 ADD。

## 数据与因果性

- 日线历史冻结在信号日；优先从 Parquet 提取，本地未覆盖或复权因子不完整时，用同花顺历史日线逐股回补。原始价与前复权价成对核对并统一到信号日；原始日线、读取时点和内容摘要随信号输入保存，重放不访问当前接口。
- 最新快照补齐涨停池、炸板池的开盘及最高价，先验证批次日期，再与腾讯逐股日期及价格核对。价格从元转换到原池的千分之一元；不覆盖已有有效字段，不将批次就绪时间视为逐股成交时间。
- “昨日涨停池”的成员资格、连板信息保留；其当前价格和涨幅不能作为昨日 K 线。新快照中的昨日价格统一来自明确交易日的日线；缺失时保持未知。
- 备用日线仅在当前盘后或次日 09:30 前获取，最多回补 100 只候选股票，每次准备最多约 45 秒、2 路并发；超时、限流、错日或复权不一致的股票保持缺失，后续准备再重试。已冻结计划不追溯改写。远端回补范围限于当日池、昨日池等已知代码，不等于替代本地全市场历史数据。
- 研究页面只读取本地及已经缓存的备用日线，不因页面刷新批量请求历史接口。历史接口在本次接入中固定为 `1d`，不引入 5 分钟 K 线。
- 当天发现的股票必须存在于已冻结的历史准入范围，验证分类、涨停基因、三亿元流动性及板块、情绪资格。盘前最多 100 只，全天最多 200 只，排序及上限随规则冻结。
- 同花顺机会接口按最多 50 个代码分组、20 条分页，保留同一股票多条异动。数量单位未明的竞价量不用于撮合容量；快照响应时间不当作行情时间。当前与文档的终态枚举均兼容。
- 竞价、板块与候选依据随联合行情帧持久化；主账户与影子账户复用同一输入。重放不访问实时 API。日线/开盘假设执行器拒绝盘中条件计划。
- 仍使用 HTTP 采样和现有保守成本模型；不承诺 09:24 抢单、封板排队或收盘集合竞价成交。T+1 与持仓风险保护继续生效。

## 使用与启用

主账户“下一交易日计划”的盘中条件计划按入池排序、共同准入门槛、仓位与成交纪律分区展示，六类买点列出适用股票类型、完整时间窗口及触发阈值，参数读取本计划冻结值。逐股表保留冻结观察池顺序，展示分类、信号日连板与涨跌幅、成交额、匹配历史前提的可观察买点和静态准入状态；历史前提匹配不等于盘中已经触发。区分静态准入通过、待成交额确认和资料待核对三种状态，支持名称/代码搜索、类型及状态筛选，每页 10 只。相同冻结计划的定时刷新保留搜索、页码和折叠状态。

V5 账户可直接在“交易执行方式”选择“盘中条件执行”并保存，不要求先完成整日影子验证。新的方式用于后续尚未冻结的计划，既有计划与历史成交保留原执行方式。独立的 `dragon-risk-v1` 新政策首次手动启用也不再要求整日报告，仍须当前版本配置及基础行为检查通过，并按整体切换流程结清旧仓；人工参数可直接排队到后续计划并标记未验证，AI 候选和主动提交的研究继续完整验证。

可另外点击“启动影子观察”。系统在当日17:00后或次日09:30前创建独立影子账户并冻结下一交易日计划，不改写已有主账户、计划和账本。09:30前冻结的V5盘中计划可以执行，09:30起拒绝补造。常驻服务采集并顺序消费行情，17:00起核验上午、下午完整覆盖、竞价与市场输入、冻结计划及行情摘要、订单和成交重放，以及最终收盘净值。提前调用核验只返回等待状态，不写入失败或通过报告。报告绑定当前执行源码指纹，核验结果独立保留，不再阻止选择执行方式。

点击“查看影子观察进度”立即打开进度窗口，展示常驻服务心跳、最近影子交易日、实际消费的行情次数、模拟成交数与最近行情时间，以及盘后核验的逐项结果。点击“刷新进度”读取最新记录；查看进度不重新登记，也不提前触发核验。候选数、观测次数、成交数均不等于全天有效覆盖已经通过。

点击进度窗口中的“N 只 · 查看候选明细”打开独立候选弹窗，每页 10 只，可搜索名称或代码，按股票类型、信号日买点筛选。名单顺序直接读取指定信号日的冻结观察计划；分数、评分因子、风险扣分、股票分类说明和买点依据读取计划摘要绑定的原始快照，不以当前评分或原开盘计划的 SELECTED 审计结果替代。接口 `GET /api/paper/entry-observation/candidates?signalDate=YYYY-MM-DD&page=1&pageSize=10&q=&stockClass=&buyPoint=` 仅查询盘中观察影子账户，原始快照丢失或摘要不一致时明确报错。

观察名单先按快照分数降序、同分代码升序纳入有冻结历史的未持仓股票，再按代码升序补入历史准入范围中的合格股票，盘前最多 100 只。入池不等于已具备买入资格：明细分别展示信号日静态准入检查和待盘中确认的条件，例如信号日成交额不足三亿元时需等待当日成交额达到门槛。信号日的六类买点标签只解释历史特征，未标注者显示“待盘中识别”，下一交易日必须重新触发买点。历史补充股缺少原池评分或分类细分说明时明确显示未知，不重新计算。

弹窗顶部统一展示“入池依据与准入核对”和“评分依据”，列表不再逐股重复通用说明。评分因子、权重、公式按整份冻结名单去重，不受分页与筛选影响；不同规则分别列明适用类型和候选数量。每行只保留个股的冻结分数、原始分与风险扣分、入池来源、准入结果和特有待确认项。

点击进度窗口中的“影子模拟成交 · N 笔”打开独立成交明细弹窗，按所选观察交易日展示影子账户逐笔成交，包含分批成交；每页 10 笔，服务端分页，按交易日、数值成交序号倒序稳定排列。接口 `GET /api/paper/entry-observation/ledger?date=YYYY-MM-DD&page=1&pageSize=10` 只读取盘中执行验证影子账户的账本，不混入主账户或其他影子账户。

进度窗口另设固定的“全部历史成交”入口，显示累计成交数和最近成交日期，不随最新会话或自然日切换而隐藏历史记录。明细默认查询全部日期，也可按成交日期查询；切换日期回到第一页，日期筛选不改变完整观察期盈亏口径。最近执行信息排除周末误建会话；独立盘中观察账户周末不新采空帧、不创建或推进会话，已有记录保留用于核查。

明细顶部展示观察期总体盈亏、当前持仓浮动盈亏、当前权益与观察起始权益，另设完整观察期的个股汇总区，每只股票只显示一次，不受日期与分页影响。成交行展示当前估值价、估值日及本笔盈亏：买入行按该批剩余股数与剩余成本计算浮盈亏（含买入费用）；卖出行按该笔净收入减实际成本显示已实现盈亏（含买卖费用）。按完整成交历史、T+1 和先进先出规则还原各批剩余数量及成本，并核对当前账本；资料缺失或无法核对时保持未知。已售出的买入批次不重复显示已实现收益。

观察起始基准为首个影子执行会话的期初账本，避免继承主账户的历史盈亏被计为观察收益。总体盈亏为当前权益减去观察期初权益；个股汇总为该股观察期内全部成交现金流加当前持仓市值，再减观察期初持仓市值，包含已实现收益及费用；浮动盈亏单独按当前持仓市值减剩余批次成本计算。全部使用影子账本已记录的估值，并显示账户更新时间。日期与分页只筛选成交。读取过程校验账户 revision，账户并发更新时重读或提示刷新，不拼接不同版本的盈亏数据。

`POST /api/paper/entry-observation` 启动观察；`GET /api/paper/entry-observation` 只读进度；`/api/paper` 返回 `entryObservation` 摘要状态；`/api/paper/settings` 接受 `entryExecutionMode`（`next-open` / `intraday-conditional`）。接口仍校验执行方式及 V5 兼容性；缺少事前冻结的候选历史、实时盘口或其他必要行情时，执行器停止相应新增买入，不补造成交。

合成测试覆盖六类触发、缺数据、涨停不可成交、同股去重、到期和重启，以及一整日合成帧的影子执行与重放。合成测试不能充当真实交易日验证报告。
