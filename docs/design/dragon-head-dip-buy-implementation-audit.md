# dragon-head-dip-buy 实现核对

日期：2026-10-22。状态：部分实现，尚不能按原始 Skill 完整验收。

验收依据：[原始 Skill](../skill/dragon-head-dip-buy/SKILL.md)、[8 项量化方案](dragon-head-dip-buy.md)、[此前缺口分析](dragon-head-dip-buy-gap-analysis.md)。本次核对当前工作区源码、现有本地数据库的只读查询、真实 Parquet 数据及合成场景，不修改账户或历史计划。

## 结论

V5 已使买点参与新增建仓决策，并增加炸板池、首阴和假阴 EOD 候选。它是现有模拟交易引擎的选股政策扩展，尚不是原始 Skill 全部战法和纪律的完整执行程序。

此前“V5 具有龙头低吸完整能力”的表述需要收窄为“V5 已接入四类买点的盘后建仓资格”。测试通过证明当前规则按实现执行，不能证明原始需求全部实现。

## 阻止“完整实现”验收的缺口

### 1. 六种买点仅有四种进入建仓决策

依据：`backend/domain/signal-selection.js:128`、`backend/domain/trading.js:865`、`backend/services/eod-candidates.js:7`。

- 普通/炸板候选通过的买点集合只有打板、炸板低吸。
- 首阴和假阴仅对 `candidateSource="extra"` 有额外放行条件。
- 仅命中 `auction-dip` 或 `late-dip` 的股票仍被建仓闸门拒绝。
- EOD 候选生成器也只挑首阴/假阴，没有覆盖普通强势股的竞价和尾盘低吸候选宇宙。

合成计划逐一核验六种标签，放行结果为：打板、炸板、首阴、假阴通过；竞价、尾盘不通过。这里的“通过”仅指在其他条件满足时生成 OPEN 订单。

### 2. 成交时点仍是原有盘后系统的设计边界

依据：`backend/services/review.js:86`、`backend/domain/trading.js:969`、`backend/domain/realtime.js:35`、`:69`、`:283`。

系统收盘后保存信号，冻结次一交易日计划；普通 OPEN/ADD 在 09:35 后失效。实时交易时段从 09:30 开始，并排除 14:57 起的收盘集合竞价。

因此它不能执行原 Skill 的“涨停瞬间打板”“首阴当天尾盘确认后买入”“09:24–09:25 集合竞价低吸”“尾盘集合竞价介入”。假阴后低开的形态在当天盘后确认，再用于下一交易日买入，也晚于原战法的入场日。

此前缺口分析已明确选择“盘后冻结、盘中不重算买点”。按该约定，这是产品边界；按原始 Skill 完整复刻验收，则是尚未覆盖的执行能力。不能用已有实时轮询器证明这些买点的原始时点已经落地。

### 3. 主战资格和“不补仓”没有形成完整硬约束

依据：原 Skill 的硬性筛选和“不补仓”条款；`shared/stock-class.js:53`、`backend/domain/trading.js:763`、`:868`、`:938`。

- V5 新建仓只排除明确的平庸型，未强制主战买点属于已确认的龙头。合成验证中，未分类、成交额 100 万元的高分打板行仍能生成 OPEN；3 亿元门槛当前只参与龙头分类，并非所有买入的硬过滤。
- 持仓仍可因评分至少 88 且目标仓位不足而生成 ADD，未按龙头低吸主战与波段备用战法区分权限。合成验证实际产生“高分信号延续，补足目标仓位”的 ADD。
- 不同买点/主辅层级没有独立预算与优先级，主要沿用统一评分排序、总目标仓位分摊和账户单股上限。
- 龙虎榜/辨识度、基本面重大利空、上市前五日排除、量比和均价线承接等原 Skill 条件没有形成完整、可验证的数据与决策链。

这不等于现有通用引擎的 ADD 或保守仓位配置本身错误；它说明通用 V5 政策不能直接当作原 Skill 的专用执行规则。

### 4. 真实字段链路还有缺口

依据：`shared/scoring.js:204`、`:610`、`shared/buy-point-type.js:194`、`:236`、`backend/services/review.js:169`。

只读抽查 2026-10-19 至 2026-10-21 的归档：

| 归档日     | 炸板候选数 | 缺开盘价 | 缺最高价 | 完整板块涨幅上下文 |
| ---------- | ---------: | -------: | -------: | ------------------ |
| 2026-10-19 |         20 |       20 |       20 | 无                 |
| 2026-10-20 |         29 |       29 |       29 | 无                 |
| 2026-10-21 |         19 |       19 |       19 | 无                 |

尾盘跳水标签需要最高价计算回落；仅将炸板行接入候选池，没有补齐这些字段，仍不足以让该类标签完整运行。并且“盘后时刻为尾盘”不能证明回落发生于最后 30 分钟。

另一个实测问题是 `market.previous` 的价量字段语义。它是昨日涨停股票在当日的表现池，不能把所有字段都当作昨日 K 线。2026-10-21 归档中，52 个具有同期日线的成员价格全部匹配当日收盘，仅 1 个碰巧匹配前日收盘。与 10-20 的原始涨停归档比较，54 个匹配成员有 53 个价格不同、38 个涨幅不同。

但 `annotateBuyPoint` 会把 `prevRow.price/change` 用作昨收/昨涨幅，而普通及炸板候选没有统一采用 EOD 昨日字段。合成例子：真正昨收 10、今日开盘 9.4、收盘 10.5，应推导低开 6%；误用当日收盘 10.5 后会算成低开约 10.48%，改变买点归类。

完整板块均值只在调用方提供 `market.sectorPerformance` 时保存；当前市场采集没有生成这份输入。降级检测器对应分支会跳过，而非已经完整运行。

### 5. 历史重构回测还没有覆盖 V5 的候选宇宙

依据：`backend/services/history.js:411`、`:435`。

当前历史评分重构向 `analyze` 传入 MA5、历史特征及首阴参数，没有传入炸板候选行、EOD 额外候选及其昨日数据；保存的历史评分只有涨停 `stocks`，没有 `brokenStocks` 和 `extraStocks`。

回测内核可以处理携带这些字段的快照，但正常历史重构入口没有提供完整输入。因此“回测计划声明 V5”不等于“已经测过 V5 全部新增战法”，更不能据此声称有完整的真实历史或前瞻效果验证。

## 验证与建议顺序

本次针对买点、情绪、分类、退出、降级、T 质量、观察分级、选股、EOD 候选、交易和实时执行的 207 项现有测试全部通过；另运行了六类买点放行、低流动性未分类买入、ADD 及昨日字段语义的诊断场景。

建议先明确验收目标：若保留盘后系统，则应命名为“dragon-head-dip-buy 的盘后量化改编版”；若要求原 Skill 完整执行，还需补充可事前冻结的盘中条件单、候选监测与买点专属时序。

按依赖关系补齐：

1. 校正昨日字段、补齐炸板 O/H 与完整板块输入。
2. 明确主战/辅战/波段的资格、补仓权限、买点集合及预算。
3. 在确定的时序边界内完成竞价与尾盘买点执行。
4. 历史重构接入同一候选管道，核验全部可交易类型。
5. 用新冻结的 V5 计划及独立窗口记录验证，保留已有历史计划。
