

\## 一、系统已有的量化基线（不用重复做）

已量化 位置 

6 因子评分（封板质量/封单/换手/首封时点/板块协同/连板结构） shared/scoring.js 

市场情绪分（涨停数/封板率/最高板） shared/scoring.js

\## 二、可以量化的优化方案（按优先级排序）

\### 方案 1：情绪周期分类器 —— 把"上升/高潮/退潮/冰点"变成仓位闸门

skill 原文（定性） ：



\- 上升期：连板高度持续打开、涨停多、炸板率低 → 6-8 成仓

\- 高潮期：连板高度极高、市场亢奋 → 3-5 成

\- 退潮期：高位股补跌、炸板率高 → 0-2 成

\- 冰点期：连板极低、涨停稀少 → 0 成

量化规则 （每天收盘后计算一个情绪分，映射到仓位上限）：



`炸板率 = 炸板数 / (涨停数 + 炸板数)

最高板趋势 = 今日最高板 / 过去5日最高板均值

昨涨停溢价率 = 昨日涨停股今日平均涨幅



情绪分 S = 0.4 \* 涨停数归一化 

&#x20;       + 0.3 \* (1 - 炸板率) 

&#x20;       + 0.3 \* 最高板趋势



仓位上限 = f(S):

&#x20; S >= 0.7 → 8成 (上升期)

&#x20; 0.5 <= S < 0.7 → 5成 (高潮期)

&#x20; 0.3 <= S < 0.5 → 2成 (退潮期)

&#x20; S < 0.3 → 0成 (冰点期)`



接入点 ： shared/risk-limits.js 增加一个"账户级仓位上限"约束；赛马时作为每个策略变体的参数闸门。



预期收益 ：退潮期强制空仓是 skill 反复强调的"最高级操作"，这是目前系统最缺的过滤器。



\### 方案 2：买点类型分类器 —— 给每笔信号打一个"买点标签"

skill 定义了 6 种买点 ，但系统当前对所有涨停股用同一套评分，不区分"你是因为什么逻辑买的"。



量化规则 （对每只候选股判定买点类型）：



买点类型 量化判定条件 打板 盘中涨停且封板，首封在 10:30 前 炸板低吸 今日曾涨停但收盘未封，从涨停价回落 3%\~7% 首阴低吸 连板 ≥3 后首次收阴，阴线实体 ≤5%，5 日均线未破 假阴跌停低吸 昨日收假阴（高开低走但收盘未跌），今日竞价低开 ≥8% 或跌停开盘 早盘竞价低吸 昨日涨停/大涨，今日集合竞价低开 ≥5% 尾盘跳水低吸 尾盘 30 分钟内从日内高点回落 ≥3%，非跌停



接入点 ： shared/scoring.js 增加`buyPointType` 字段；回测时按买点类型分组统计胜率/盈亏比。



预期收益 ：这是赛马策略家族的天然分化维度——不同买点类型的胜率和赔率差异巨大（skill 自己也说打板确定性最高、假阴跌停赔率最高）。有了标签就能让赛马自动淘汰差的买点类型。



\### 方案 3：股票分类器 —— 路由到不同策略家族

skill 说 ：连板龙头型 / 强势反包型 / 波段震荡型 / 平庸型，不同类别打法完全不同。当前系统把所有涨停股混在一起评分。



量化规则 ：



`连板龙头型:

&#x20; 连板数 >= 3

&#x20; AND 是所属行业板块内最高板（板块领涨）

&#x20; AND 成交额 >= 3亿



强势反包型:

&#x20; 近10日内有涨停（涨停基因）

&#x20; AND 未达连板龙头标准

&#x20; AND 收盘价站上20日均线（趋势向上）



波段震荡型:

&#x20; 有题材标签

&#x20; AND 近20日振幅适中（10%\~25%）

&#x20; AND 非涨停股或首板



平庸型:

&#x20; 不满足以上任一 → 直接排除（不进入候选池）`



接入点 ： backend/domain/signal-selection.js 选股阶段先分类，再用不同评分权重；连板龙头型用`relay` 权重，强势反包型用`balanced` ，波段震荡型用`first` 权重——系统已有 3 套权重预设，正好对应。



预期收益 ：避免"在平庸股票上浪费生命"，从源头过滤掉低质量候选。



\### 方案 4：金字塔减仓参数化 —— 把 skill 的减仓表变成可优化参数

skill 规定 ：



\- 第一个涨停（+10%）减 3 成

\- 第二个涨停再减 2 成

\- 第三个涨停+再减 1 成

当前系统 有减仓动作但规则是固定的。



量化方案 ：把减仓比例作为赛马的可优化参数：



`减仓比例向量 = \[p1, p2, p3, ...]

&#x20; p1: 第1个涨停后减的比例（skill: 0.3）

&#x20; p2: 第2个涨停后减的比例（skill: 0.2）

&#x20; p3: 第3个涨停后减的比例（skill: 0.1）



赛马时让 AI 提出候选：\[0.2, 0.2, 0.1] / \[0.4, 0.3, 0.2] / \[0.5, 0.2, 0.1] 等`



接入点 ： backend/domain/trading.js 的减仓逻辑从硬编码改为参数化； shared/strategy-params.js 增加 schema。



\### 方案 5：卖出信号检测器 —— 在现有止损之外增加主动止盈信号

skill 列了 6 个主动卖出信号 ，当前系统主要靠固定止损（-5%）和 T+1 约束。



量化规则 ：



卖出信号 量化定义 放量滞涨 今日成交量 > 20日均量 × 1.5，且涨幅 < 2% 炸板不回封 盘中炸板 ≥2 次，且 14:30 后未回封涨停 跌破5日均线 收盘价 < MA5（短线趋势破位） 高位长上影 (最高价 - max(开,收)) / 收盘价 > 3%，且股价处于20日新高 板块集体退潮 同行业涨停数较昨日减少 ≥50% 情绪周期切换 情绪分 S 从高潮期跌入退潮期（方案1输出）



接入点 ： backend/domain/trading.js 增加`checkExitSignals(position, marketData)` 函数，每日收盘后检查。



\### 方案 6：判断失误降级检测器 —— 自动识别"买成跟风股"

skill 说 ：发现是跟风股后要降级处理，不能死扛。



量化规则 （持仓期间每日检查）：



`降级触发条件（满足任一）：

1\. 板块内有另一只股票连板数 > 持仓股（不是最强的）

2\. 持仓股今日涨幅 < 板块平均涨幅的 50%（跟涨不领涨）

3\. 持仓股今日炸板 ≥2 次且未回封（封不住）

4\. 持仓股今日换手率 > 15% 但涨幅 < 3%（放量滞涨）



降级后动作：

&#x20; 连板龙头型 → 强势反包型：仓位降1档，预期收益目标从30%降到10%

&#x20; 强势反包型 → 波段震荡型：仓位再降1档，改为快进快出`



接入点 ： backend/services/paper.js 每日结算时调用降级检测。



\### 方案 7：做 T 质量追踪 —— 量化"做T越做越错"

skill 的错误模式 ：做 T 变成补仓，越套越深。



量化规则 ：



`每笔做T记录：

&#x20; T买入价 / T卖出价 / 当日T盈亏 / 是否当日了结



连续做T质量评分：

&#x20; 最近N笔做T的平均盈亏 < 0 → 标记"做T状态差"

&#x20; 连续2笔做T亏损 → 触发"停手3天"规则（skill：连续做错两次就停手）



做T仓位上限动态调整：

&#x20; 胜率 > 60% → 允许2成仓做T

&#x20; 胜率 40%\~60% → 限1成

&#x20; 胜率 < 40% → 禁止做T`



接入点 ： backend/storage/paper.js 增加做T记录表。



\### 方案 8：观察池 A/B/C 分级 —— 把"重点关注/一般关注/备选"量化

skill 定义了 A/B/C 三级 ，当前系统只有排名没有分级。



量化规则 ：



`A级: 评分 >= 80 AND 买点类型 ∈ {打板, 炸板低吸} AND 股票分类 = 连板龙头型

B级: 评分 >= 60 AND 非平庸型

C级: 评分 40\~60 或 强势反包型/波段震荡型

排除: 评分 < 40 或 平庸型`



接入点 ： backend/domain/signal-selection.js 输出时附带 grade 字段。



优先级 方案 理由 

P0 方案 1（情绪周期仓位闸门） 退潮期空仓是 skill 最高频的纪律

P0 方案 2（买点类型标签） 赛马分化的基础维度，有了它才能按类型统计胜率 

P1 方案 3（股票分类路由） 从源头过滤平庸股，提升候选质量 

P1 方案 5（卖出信号检测器） 当前止损只有固定 -5%，缺少主动止盈 

P2 方案 4（金字塔减仓参数化） 已有框架，改造成本低 

P2 方案 6（降级检测器） 持仓管理自动化 

P3 方案 7（做T质量追踪） 偏行为改进，需要积累数据 

P3 方案 8（A/B/C 分级） 锦上添花

核心思路 ：skill 的方法论里，真正能给系统带来超额收益的量化杠杆是 情绪周期闸门 （过滤烂时间）和 买点类型分化 （只做高胜率买点）。其余的减仓/卖出/降级都是执行层的精细化。
