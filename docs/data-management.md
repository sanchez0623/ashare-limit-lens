# 股票信息与双行业数据管理

顶部系统菜单中的“数据管理”用于分别更新股票名册、东财行业及申万 2021 一级至三级行业。范围为沪深主板和创业板，基础名册保留 ST 名称信息，交易仍执行原有筛选规则。本功能不下载 K 线、不回填指数成分、不定时抓取数据，也不依赖另一个 QuanQuant 服务或 Python 环境。

## 使用

1. 构建后运行 `npm start`，或运行 `npm run dev`；如需申万分类，在本项目 `.env` 配置 `SW_METADATA_SOURCE=lixinger` 和 `LIXINGER_TOKEN`。两个入口都启动独立的数据更新 worker；即使 `TRADING_ENABLED=false` 也能更新元数据。修改凭证配置后需重启服务；凭证不返回浏览器，不写入任务、日志或快照。
2. 打开“数据管理”，点击“更新股票名册”“更新东财行业”“更新申万行业”或“全部更新”。名册无需 Key，可独立使用。首次安装显示“未初始化”，不会在启动时自动抓取。
3. 查看当前步骤、完成数量和耗时；可以取消。浏览器关闭后任务继续，重新打开页面会恢复任务状态。
4. 成功后状态卡片和研究数据自动刷新，无需重启服务。更新时间均为北京时间，表示成功抓取时间，不代表供应商保证的历史有效日期。

股票名册独立保存为 `stock_list` 快照：沪市优先读取[上交所主板 A 股名单](https://www.sse.com.cn/assortment/stock/list/share/)，深市优先读取[深交所 A 股 XLSX 名单](https://www.szse.cn/market/product/stock/list/index.html)。上交所校验声明总数与返回数量；深交所校验完整 XLSX 文件、必需字段、代码、板块和上市日期。交易所字段中的行业分类不写入东财或申万行业。

某个交易所失败时，使用新浪 `Market_Center.getHQNodeStockCount` 与 `Market_Center.getHQNodeData` 获取完整 A 股分页，再只补齐失败市场；另一个交易所已成功的数据优先保留。两个交易所均失败时只抓取一次新浪全量。新浪单页最多 100 条，即使传更大的 `num` 也会被截断，因此逐页按 `symbol` 升序读取，校验每页长度、代码唯一性、稳定排序与前后声明总数。北交所和科创板参与源总数核验后才过滤，不把第一页当全量。源请求间隔至少 1 秒，常见约 56 页需要一分钟左右。名册 worker 每次请求超时 8 秒、最多重试 1 次；失败后可走另一个独立公开来源。缺少任一市场、分页重复、截断或备用源失败时保留上一份完整名册。

状态卡片和任务结果显示实际来源的数量，例如“上交所 1700 只、新浪 2906 只”，备用源使用原因写入结果的 `warnings`。保留 ST 名称与标记，新股票按代码追加；本次名单缺失只标记 `presentInSource=false`，不判定退市。源声明总数表示该源当次返回的名册，不保证各源更新时点和覆盖范围完全一致。

东财行业有两条当前有效链路，均无需 Key。名册已初始化时，优先请求 `https://push2.eastmoney.com/api/qt/ulist.np/get`，按名册的市场和代码生成 `secids`，每批最多 200 只，读取原生 `f12/f13/f14/f100`。每批须精确返回所有请求代码，声明总数、实际数量、代码唯一性、市场、名称与行业字段逐项校验；缺少股票不会当成空行业静默忽略。当前 4,606 只名册需要 24 批，请求间隔至少 1 秒。

原生批量接口发生网络中断或超时、有限重试仍失败时，整批改用 `https://datacenter.eastmoney.com/securities/api/data/v1/get` 的 `RPT_F10_BASIC_ORGINFO` 报表。按 `SECURITY_TYPE_CODE=058001001` 读取完整 A 股分页，校验固定总数、页数、每页长度、唯一 `SECUCODE`，再与当前名册逐一匹配；报告中的退市及范围外记录不进入当前名册。行业取 **`BOARD_NAME_LEVEL` 的第二层**，保留层级后缀，不使用旧的 `EM2016`、证监会行业、申万分类或第三层。字段层级变化、缺少目标股票、分页重复、空结果或不完整时仍拒绝发布。2026-10-24 全量核对：原生 `f100` 与 F10 当前第二层在 4,606 只股票上完全相同，详见[东财行业接口核对](eastmoney-industry-sources.md)。

HTTP 429、403 或内容校验失败不会通过切换接口绕过；只在连接类故障时启用 F10 备用。原生源记录为 `eastmoney-ulist-f100`，备用源为 `eastmoney-f10-board-level2`，页面显示实际生效来源，备用启用原因写入任务 `warnings`。股票记录保存 `emIndustrySource/emIndustryField`，F10 还保存原始 `emIndustryPath` 便于核对。

没有独立名册的旧安装仍兼容原 `clist/get` 全市场链路；若该接口连接失败，会提示先更新股票名册以启用批量链路。`stock_em` 保留旧接口的身份字段以兼容历史快照，新的基础名册不受行业请求成功与否影响。行业更新不读取延迟价格，也不覆盖行情原有有效 `hybk`：涨停池可能使用“汽车零部”等缩写，它们原样保留。

申万默认参照 `a-stock-momentum-trend` 项目的理杏仁批量链路，独立用 Node 实现。向 `https://open.lixinger.com/api/cn/industry` POST `{token,source:"sw_2021"}` 获取目录，再向 `/api/cn/industry/constituents/sw_2021` POST `{token,date:"YYYY-MM-DD"}` 一次获取全部行业成分。两次请求即可取得原始全量数据，不逐个行业抓取。目录必须有完整父子关系，每个当前三级行业必须有对应成分组；逐组校验代码、重复、父级归属及覆盖完整性，历史未知行业代码不作为当前分类。

发现多归属或只有父级而缺少当前三级归属时，额外请求一份[申万官方分类变更文件](https://www.swsresearch.com/swindex/pdf/SwClass2021/StockClassifyUse_stock.xls)，按不晚于查询日期的最新“计入日期”选取分类，“更新日期”只表示记录编辑时间。多归属只有在官方唯一分类与候选之一匹配时才能消除；只有父级的记录，须确认其官方三级代码不在当前目录，才可视为历史记录排除。官方仍指向当前三级却缺少成分、官方文件不可用、缺少对应记录或当前有效归属有冲突，均拒绝发布。核验文件仅按需批量获取一次，不逐股票请求。三级代码与指数代码不同，例如理杏仁 `280205` 对应乐咕指数 `850925.SI`，不直接比较数字代码。2026-10-24 的交叉核验见[来源核对报告](industry-source-crosscheck-2026-10-24.md)。

申万官网缺少 TLS 中间证书，本项目为该域名专用 HTTPS 客户端补充 DigiCert 根证书签名的公开中间证书，仍验证完整证书链与域名，不关闭 TLS 校验。官方 XLS 由 Node 的 SheetJS 解析，不依赖 Python。冲突股票的快照记录包含 `swVerification`：官方来源 URL、文件 SHA-256、计入日期、编辑日期、核验时间及排除的行业代码；成功任务显示核验数量。

没有理杏仁凭证时界面明确提示未配置，不自动退回数百次网页抓取。若显式设置 `SW_METADATA_SOURCE=legulegu`，则使用原乐咕行业树和各三级行业成分页，串行读取，间隔至少 2.5 秒；约 335 个行业通常需要 14 分钟以上，空行业不请求成分页。遇到 429 会继续降速，因此耗时可能更长。

后台请求默认超时 12 秒，网络及 429/5xx 最多重试 2 次；429 至少冷却 60 秒并逐次延长，尊重 `Retry-After`，同时降低后续请求频率。服务要求单次等待超过 5 分钟时结束本次任务；同一执行器后续任务仍遵守该站点的冷却截止时间。界面显示暂停原因及重试倒计时，等待期间可取消。

东财接口可能断连或限流。错误会区分远端断连、超时、域名解析失败、JSON 格式异常及 HTTP 状态，便于判断故障。未初始化时失败显示“尚未初始化，本次未发布数据”；已有快照时保留上一版。任一数据集的必需请求失败、成分不完整或出现无法核验的冲突归属时，不会发布该数据集的残缺快照。“全部更新”按股票名册、东财行业、申万行业依次执行，三项独立发布；例如东财失败时股票名册和申万仍可成功，最终显示“部分成功”。错误原因只展示一次。取消不撤销已经成功发布的数据，但会阻止后续未完成数据发布。

## 两套行业的用途

- 东财行业用于现有个股评分、板块协同及交易风控。行情自带的 `hybk` 优先，只有缺失时才从本项目已发布的东财映射补充；不再使用手写数字行业字典或固定路径的 Hikyuu `stock.db`。
- 板块研究与个股列表可选择东财、申万一级、二级、三级。申万分组只用于界面探索，不改变个股综合分、交易计划、风控或正式证据。
- 申万未覆盖股票单独计数，可以在个股行业筛选中选择“申万未覆盖”，不会混合成一个虚假的行业。
- 查看历史日期时，申万视图使用最新成功快照，并展示样本日期、分类更新时间和“按当前分类观察”。它不能当作历史时点分类，用于回测或策略晋级。历史名称、原行业、评分、计划、账本均保持原样。
- 新评分记录 `EASTMONEY_NATIVE_V1` 分类口径；旧快照及其摘要兼容。元数据每日更新不会独立开启新的评分口径。旧归档缺少口径声明时显示“原快照行业（旧版冻结口径）”。

## 存储与运行

迁移 `0030_stock_metadata.sql` 在现有 `LOCAL_DATABASE_PATH`（默认 `.sites-runtime/local.sqlite`）中保存版本化快照、股票记录、当前版本指针、任务和 worker 心跳。独立名册使用既有文本 `kind` 字段的新增值 `stock_list`，无需改表或重建旧库。旧安装未初始化独立名册时，覆盖率暂以旧东财名册为分母，并明确标记来源；首次名册成功发布后切换到独立名册。名册更新不改变东财快照、原始行情行业、评分、交易计划或归档。

数据先分批暂存，校验通过后以短事务切换指针。取消与执行器所有权也在最终事务中检查。worker 与交易循环独立运行，网络和 HTML 解析不进入交易进程。服务异常中断后，旧 worker 心跳租约最多 30 秒到期，新 worker 接管并将中断任务标为失败，可重新提交。

`DATA_WORKER_ENABLED=false` 可禁用本地执行器。非本地部署未提供执行器时，界面展示不可更新原因，不创建无法执行的任务。数据更新 worker 由启动入口管理，父进程退出时停止，异常退出会自动重新启动。

## API

所有接口沿用本项目身份与 Origin 检查；GET 不抓取外部数据。

| 接口                             | 请求与结果                                                                                                                                                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/data/status`           | `available`、`workerHealthy`、`capabilityReason`、`stockList`、`stockListFallback`、`stockEm`、`industrySw`、`swProvider`（`source/ready/description/reason`）、`missingEm`、`missingSw`、`activeJob`、最近 20 次 `jobs`。未初始化快照为 `null`，覆盖率未知时为 `null`。 |
| `POST /api/data/update`          | JSON 仅支持 `scope`：`stock_list` / `stock_em` / `industry_sw` / `all`。旧 `stock_em` 范围继续兼容；`all` 包含三个数据集。返回 HTTP 202 和 `{job,reused}`。相同活动范围复用任务；其他范围占用时返回 HTTP 409 和 `activeJob`。执行器不可用返回 HTTP 503。                 |
| `GET /api/data/jobs/:id`         | `{job}`，不存在返回 HTTP 404。                                                                                                                                                                                                                                           |
| `POST /api/data/jobs/:id/cancel` | `{job}`。排队任务立即取消；运行任务在请求或发布检查点停止。终态任务重复取消不改变结果。                                                                                                                                                                                  |

任务字段：`id/scope/status/stage/progress/results/error/cancelRequested/workerId/createdAt/startedAt/updatedAt/finishedAt`。状态为 `QUEUED/RUNNING/SUCCEEDED/PARTIAL/FAILED/CANCELLED`。进度为当前步骤的 `kind/completed/total`，重试时还包含 `retryAt/retryAttempt/maxRetries`；`retryAt` 为 UTC ISO 时间，界面按剩余秒数展示。进度并非整个任务的恒定耗时百分比。`results` 逐数据集记录生效快照、数量、新增、名称变化和行业变化，或者失败原因；申万成功结果的 `verifiedConflicts` 表示按官方文件消除的多归属数量。`stockList` 和 `results.stock_list` 包含 `sources`（各实际来源的股票数量）和 `warnings`（切换备用来源的原因）。`missingEm/missingSw` 的 `count/covered/coverage/samples` 使用当前独立名册计算；尚无独立名册时兼容旧东财名册。以上信息使用现有 JSON 字段，无需新增数据库迁移。

`GET /api/market` 追加 `industryMetadata`，仅包含当前样本代码的申万归属、快照 ID、成功抓取时间，以及 `CURRENT_CLASSIFICATION_EXPLORATION_ONLY` 用途标记；历史归档响应也使用最新申万映射，绝不回写归档。`industryContext` 记录新评分使用的东财口径，申万归属不进入评分上下文。
